# 临时产物留存、归档与跨电脑接续

## 选择同步范围

优先保障最新系统正常使用、项目接续和有效成果追溯。已闭合且无当前依赖的低价值早期试验、否决候选及过时构建中间件可明确退役到回收站；只留简短结论时不要求完整ZIP。历史报告链接本身不构成永久保存全部过程数据的理由，但退役说明必须明确旧明细/重放不再提供。现行依赖、事实源、在途任务与生产事务恢复契约继续受保护，不按日期批量清空。

以下archive-temp/restore-temp协议适用于仍决定保留的历史组；退役不改写归档校验或提供绕过开关。文件清理保存路径/理由/哈希并可逆移动，核对当前入口和保留内容；使用交接包时，换机前生成新检查点。

单目录工作区可以就地保留中间文件。直接同步时，系统、Raw/Wiki、公共与私人图、项目和当前可编辑成果随工作区同步。用户可将单个项目的过程文件保存在原电脑；重新执行相应步骤时可取回文件或重新生成。临时产物按任务状态、引用和可重建性处理；`temp` 中的生产摄入/修复/续跑记录不能整体排除。

## 处理边界

- 当前知识和工作状态完整保留。运行环境和明确缓存由检查点既有规则排除，在各机准备。
- 已完成且有审计/复现价值的历史实验按完整目录归档。完成判断由宿主结合报告作出；嵌套实验副本里的 `awaiting_agent` 不自动代表生产待续任务，目录日期也不自动证明已完成。
- 确认无引用、可重建或被替代的中间产物可进入群晖外待删除区。原路径、处理理由与校验信息应保留；建议观察30天后复核并进回收站，无自动永久删除。

当前实现先压缩经确认闭合的历史实验，不引入按名字/日期批量忽略的规则。尚未分类的temp继续保留；后续新内容仍由其任务协议决定留存。

## 归档与恢复入口

```bash
python3 .scripts/wg.py checkpoint archive-temp experiment-closed \
  --evidence projects/example/outputs/completed-report.md \
  --reason '该批次已结束，保留结果、失败尝试与复现材料' \
  --quarantine ~/WikiGraphData/pending-delete/temp-archives/experiment-closed
python3 .scripts/wg.py checkpoint restore-temp experiment-closed \
  --target ~/WikiGraphData/restored/experiment-closed
```

独立入口 `.scripts/temp_archive.py --root <工作区> archive|restore ...`。依赖项目核心Python环境及ripgrep；Agent/API调用同一确定性内核，不调用模型。

仅接收一个顶层 `temp/<name>` 目录、保留的项目/operations完成记录及理由。拒绝已归档、Git跟踪内容、符号链接目录、重复目标与目录越界。扫描文本引用时包括隐藏文件和被Git忽略的文件，跳过Git、环境、node_modules和归档包；发现其他代码仍引用该实验则拒绝自动归档。唯一例外是已经完整归档的历史脚本：必须校验原位置/归档旁两份回执一致、来源身份正确、整包SHA-256及脚本原始SHA-256一致，才允许沿实验依赖顺序继续归档；缺包、改动或无效回执均拒绝，不提供跳过参数。文本扫描是直接路径引用检查，不能证明不存在动态拼接路径，因此还需要宿主的闭合判断。

完整包保存在仓库 `archives/temporary/<name>.zip`，附带可读JSON回执。ZIP内清单记录每个原始文件的SHA-256、类型和权限，符号链接只保存目标字符串。打包后实际解压到独立暂存目录逐项复核；源或引用变化时拒绝换位。原目录整体移至指定的群晖外待删除区，并留下原位置索引、全部顶层结果文件以及报告明确引用的嵌套文件。原文件不被永久删除。

原路径的目录链接仍可进入归档索引，明确文件链接仍能读取保留下来的同字节文件。查看其余历史明细或重新运行实验时，先用恢复入口恢复完整目录。原位置保留脚本仅供查证；重新执行历史实验还需恢复其依赖的实验目录并核对旧脚本环境/路径，不保证在精简目录直接续跑。新索引列明已校验的归档上游引用脚本，回执reference_documents保留依赖出处。恢复目标必须不存在，校验整包SHA和逐文件内容，不使用不受控的ZIP提取，不执行归档中的脚本。符号链接最后创建，恢复过程不通过链接写文件；历史外部链接不承诺在另一台电脑可达。

归档包、原位置索引、保留的引用文件和完成报告都位于工作区，因此进入后续完整检查点；外部待删除原件不进入跨机包。这使知识/成果保持完整，历史碎文件变为少量可恢复包。它不删除已经发布的旧增量备份包，既有备份祖先链继续保留。

换位使用本机原子改名，不在跨文件系统错误后改成copy-and-delete。归档包已经发布但换位中断时，原目录或指定待删除原件仍可恢复；按回执核验后处理，不直接覆盖工作目录。归档执行期间只需对应历史实验停止写入，不需要停止全系统正常使用。

## 验收

`.scripts/test_temp_archive.py` 验证真实压缩/解压、原路径明细引用、链接与二进制保真、源漂移、损坏包、活跃代码依赖、归档依赖链及变更/损坏拒绝、边界/目标碰撞，以及归档后检查点仍保留活动任务和压缩历史。归档不会代替事实层的受管摄入、删除或图操作。
