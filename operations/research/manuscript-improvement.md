# 论文撰写与优化持续工作

> 在 `research` 持续工作中承载论文起草、优化与接续，落笔入口为 `artifact.write` 的 `academic-manuscript` profile。本规范是论文工作方法的单一维护源，复用 `workspace_state` 保存事项与记忆；skill 提供发现入口，shared 只执行路由、状态校验与存储，全文阅读、科学判断和写作由宿主 Agent 完成。

## 入口与范围

保持论文所在的 `research` 工作上下文，按项目约定恢复状态，定位用户指定或已确认的当前版本、主文、图表、补充材料和参考文献。不要仅凭修改时间选版本。目标期刊、语言、篇幅和已接受意见优先从当前上下文确定；只补问确实影响交付且无法从材料确定的信息。

- **讨论或评估**：读取本规范和论文，提出有证据的建议，不自动修改文件。
- **从材料起草**：无完整稿件时，读取研究记录、方法、数据、图表与文献，建立论证结构并写出证据支持的稿件；未完成研究不写成既成结果。
- **整篇优化**：以已有稿件为基础或参考，保留有效内容，根据科学贡献、证据及当前薄弱处安排顺序。结果已完整时可先改结果，再处理方法、讨论和结论，最后统一引言、摘要与标题。已授权的修改连续完成，不要求用户逐阶段批准。
- **接续或局部修改**：尊重用户指定阶段和范围，复用已经完成的阅读与已接受结论；单独改摘要使用 `academic-abstract`，单独取标题使用 `manuscript-title`，单独写引言使用 `manuscript-introduction`，不把局部任务自动扩为整篇改稿。

实际起草或修改前加载一次：

```bash
python3 .scripts/route.py --capability write --capability-profile academic-manuscript
```

该 profile 派发共享写作规则与本流程；摘要阶段复用[摘要规范](academic-abstract.md)，已加载则不重复。物理论文另组合[物理论文注意力清单](physics-manuscript-editing.md)，其他学科使用适合其论证方式的规范。期刊的硬性格式要求按需查当前官方说明，不把一次 PRL 修改经验设成所有论文的模板。

## 建立与接续持续工作

论文是 [research](../RESEARCH.md) 中的一项持续工作，复用[工作区](../WORKSPACE.md)的权威事项、记忆和校验，不新增状态机或自动定时运行。通用方法、入口和[事项正文模板](templates/manuscript-work-items.md)随仓库发布；稿件、项目状态、工作实例和基线快照保持既有私有边界，第三方环境只声明依赖。

先读取目标项目已有 `notes/status.md`（若存在），然后调用 `python3 .scripts/route.py --task research` 并恢复工作区。有 `workspace.yaml` 时调用 `python3 .scripts/workspace_state.py recall '<项目路径>'`；已有 `.research-memory` 时沿兼容入口恢复，不静默迁移。目标论文已有合适的研究工作区时直接复用，避免重复事项；新项目或尚无工作记录的稿件目录在已有开始持续工作的授权内初始化：

```bash
python3 .scripts/workspace_state.py init '<项目路径>' --profile research --domain manuscript --name '论文撰写与优化'
python3 .scripts/workspace_state.py item add '<项目路径>' --type manuscript --title '论文撰写与优化' --state active --next-action '当前具体下一步' --stdin < '<暂存事项正文文件>'
```

通过现有 `item update` 更新同一事项；事项正文按模板保留原始比较基线、当前主稿与候选稿地址及各自状态、文献库、已完成工作、阅读与验证覆盖、待办和下一步。用户选定的主稿与候选不混同，版本不按修改时间猜测；首次建立基线时保留已有版本，必要时在项目内保存只读用途的副本或记录已有 Git 版本。用户认可的定位与重要取舍通过 `memory add` 保存，变化时按 `supersedes` 留痕，不仅保存在聊天里。

每次接续从 recall 定位当前事项，再读相应 `.workspace/items/` 正文和所需记忆，核对实际稿件与证据是否变化。阶段结束更新事项的产物、已完成内容、剩余问题和具体下一步，并运行 `doctor`。`notes/status.md` 是自动投影，不手工替代权威记录；没有新进展时不重复记录旧决策。普通局部润色无需额外建立工作区。

## 主文档命名与版本

论文主文档统一采用 `<短名>_v<N>.<扩展名>`，如 `paper_v1.tex`、`paper_v1.docx`；同版 PDF 使用相同文件名主体，如 `paper_v1.pdf`。短名采用稳定、易识别的论文简称，不把日期、修改内容或 `revised/final/latest` 等状态词串入主文档名；日期与修改说明记录在项目事项或版本说明中。

版本号默认从 `v1` 开始，每形成一版新的可交付修改稿递增为 `v2`、`v3`；同轮编辑、临时保存和重新编译不单独升版，已交付版本保留以便比较。已有明确版本序列时接续原编号；历史稿没有一致编号时，以当前确认稿作为新序列起点，保留历史文件并记录旧名与新名的对应，不臆造历史版本。

当前事项明确记录短名、当前版本、主文路径、对应导出文件及上一版位置。切换版本或规范旧名时同步当前入口与受影响的构建引用，确认源文件与导出内容对应。局部摘要或引言修改一旦交付为完整稿，也遵循本约定；章节候选、修改说明和 diff 可保留用途标识，不与主文混同。

## 文献需求与摄入后接续

任何阶段发现文献缺口均可提出具体需求。先复用已有核验、查询知识库和必要公开来源；可用文献不必全部先摄入。需要用户提供全文、补充材料或授权摄入时，给出题名及 DOI/稳定链接、待核验论断、影响章节和是否阻碍该主张成立，不把所有文献需求变成必经审批。

需要跨回合跟踪时，按模板创建 `question` 类型事项并标记 `literature`；记录所需材料、已核验范围、摄入授权情况、相关稿件版本及恢复位置。复用现有状态：可继续查证为 active，未安排的补充为 planned，等待用户材料为 waiting（填写 waiting_on 与 review_at），具体论断因缺失证据无法推进为 blocked（填写 blocked_by）。只限制依赖该证据的论断或工作项，其余写作继续；实际用户暂停整个工作时才停止整体推进。复核日期仅供接续时检查，不意味着已设置提醒或自动催促。

用户授权摄入后，临时调用 ingest 能力，按仓库的预热、参数与受管事务约定执行，不直接写 Raw；授权已覆盖的操作不重复询问。在原文献事项记录返回的真实文献标识和 Raw/Wiki locator、实际核验范围及受影响主张。摄入完成不等于论断已验证：回到原文核验，再更新文献判断与引用；明确处理完相应缺口后才将事项设为 done 并填写 outcome，恢复原稿件位置的写作。失败则记录真实原因，保留恢复位置，不声称已入库或据未核验内容定稿。未授权摄入时可继续阅读公开材料并交付候选文字。

## 准备：Agent 通读全文

**整篇优化前，Agent 必须自行通读已有全文，包括主文各节、图表及图注、结论、附录和补充材料。** 从材料起草时全面阅读已提供的研究材料，局部任务按其影响范围阅读。准备工作不转交用户；通读不是只检索关键词、读取摘要与结论，或用旧讨论替代阅读。长稿可分段完成，结构化提取不足以判断的图表与版式再作局部视觉检查。

通读时形成轻量的“科学问题—现有障碍—方法作用—核心结论—支撑证据—适用边界”对应，记录关键页码、章节、图号或源文件位置即可，不强制额外表格或状态文件。特别区分：

- 方法组件的已有性与本文新增的能力、机制或资源优势；使用一种表示或优化方法本身不自动构成创新。
- 理论证明、数值观察、真实实验与预测检验各自支持什么结论；观察到的规律不能直接升级为普遍保证。
- 比较的任务、对象族、规模、预算、先验、指标与统计条件；与个别基线相比的优势不扩张为全面领先。

已经在当前连续工作中通读且未变化的材料不必每轮重读；有变更时读取变更及其依赖。上下文不足以确认此前阅读覆盖时补读。材料缺失或无法读取时明确说明实际覆盖范围，先完成证据充分的工作，不声称已通读，也不编造缺失部分；仅在缺口阻止关键判断时请求补充。

## 改稿前：评估核心贡献

复用最新认可的科学问题、贡献排序和背景动机；缺失或发生实质变化时，按需组合 [manuscript-question](manuscript-question.md)、[manuscript-evaluation](manuscript-evaluation.md) 与 [manuscript-motivation](manuscript-motivation.md)。首次形成定位时按评估规范展示核心问题、贡献分类、重要性与证据强度及推荐主线。本流程不复制各能力的方法；优先突出重要且证据充分的贡献，明确补证需求。

按评估规范处理定位确认；复用已认可主线和未变化的评估，不增加逐阶段批准。摘要、标题、引言和主结果围绕同一排序展开，新增证据或期刊目标变化时才更新相关评分。单纯语言或格式调整不重新启动评估。

以下为各部分的写作责任，不规定执行先后。先基于原稿说明保留、重组、压缩和补充的理由，再按当前任务推进；方法、结果、讨论和结论共同支撑科学主线。

## 一、摘要：确定科学主线

按[摘要规范](academic-abstract.md)整合科学问题、贡献和背景动机，不另建重复模板。突出核心发现、必要方法与代表性证据及科学意义，篇幅和顺序按论文特点安排。

摘要承担整篇论文的贡献提纲。每个强主张必须能定位到正文或补充材料，并保留成立所需的对象和条件。用户希望“更强”时，优先修复结论不清、证据层级混乱或实验意义被埋没的问题；区分可通过表述改善的说服力和需要新增证据的主张。

## 二、标题：准确凝练贡献

按[标题拟定规范](manuscript-title.md)综合已认可的核心科学问题、贡献重要性与证据强度及全文内容拟题，不只根据摘要取标题。需要独立入口时调用 `python3 .scripts/route.py --capability manuscript-title`；在本流程内复用已完成的通读、评估与共享落笔约定，直接加载标题规范即可。

标题方法与候选比较统一在专项规范维护。已有用户选定的标题与术语作为基线，证据冲突时说明并修正；整篇修改已经授权时直接采用有依据的推荐，不增加选标题审批。

## 三、引言：论证贡献为何重要

按[引言规范](manuscript-introduction.md)基于或参考原稿组织完整引言；独立入口为 `python3 .scripts/route.py --capability manuscript-introduction`。本流程复用已通读材料、已认可定位与文献核验结果，直接加载专项规范，无需重跑各项定位能力。

引言规范统一维护背景动机、文献定位、本文切入点与贡献论证，避免重复规则。整篇改稿已有授权时直接落实，贡献承诺须与后文证据对应。

## 四、全文：完成论证与证据闭环

正文应语言利落易读、逻辑紧凑清晰；按独立的科学任务划分小节，避免把连续论证切成过多短节。若非必要，谨慎使用防御性语句：直接陈述有证据支持的发现，将必要的适用条件与限制集中放在相关方法或讨论中，避免反复自我限定；保留影响结论成立的条件和重要反例。

以引言承诺的贡献为线索检查和修改全文，优先解决影响结论可信度的问题，再处理语言与行文。核查重点按稿件类型取舍：

- **方法与推导**：假设、符号、目标函数、归一化、算法步骤和成立条件是否明确；复杂度的资源对象与参数范围是否清楚；证明、经验规律和启发式解释是否区分。
- **结果与比较**：指标定义、单位、数据划分、误差条和样本量是否一致；训练、验证与测试的用途是否清楚；比较是否公平，单点精度与尺度规律是否混淆。
- **图表与叙事**：图轴、图例、图注和正文是否对应，数据能否支持结论，关键控制条件是否可识别；示意图与实际方法是否一致。
- **实验与可复现性**：实验平台及实际使用规模、测量协议、噪声、预处理、超参数和代码/数据可用性是否足以理解结果；主文与补充材料能否互相定位。
- **讨论与边界**：结论是否超出对象族或证据，限制是否解释了适用范围，意义是否由结果推出；参考文献是否支持具体主张。

已确认且在授权范围内的文字、符号、引用和一致性问题直接修正。需要新增数据、重跑实验或作者确认的事实问题单独列明；不伪造数据、不把未验证推断写成事实，也不把缺失证据包装成已经解决。用户暂不补充的材料保留为已知限制，避免反复追问。

## 回查与交付

完成全文后反向核对摘要、标题、引言：承诺的贡献是否均有证据，正文发现的边界是否已反馈到前文，指标、数字、比较条件、术语和真实实验规模是否一致。保留多轮讨论中已接受且仍受证据支持的核心结论，不因局部压缩静默丢失贡献。

遵循上述主文档命名与版本约定，交付可定位的源文件、修改说明和 diff，明确当前主文、补充材料、参考文献及导出文件。LaTeX 构建、引用/标签检查与受影响页面的局部视觉抽检复用摘要规范的交付规则；其他格式使用相应文档能力。检查通过只说明相应构建和一致性结果，不等于科学结论经独立复现或保证送审、录用。

汇报优先说明贡献表达如何改善、哪些实质问题已修复及尚未解决的证据缺口，避免只列润色数量。写作产物不自动摄入知识库，不自动投稿或发送给他人。

最后与原始基线及上一版比较科学聚焦、论证完整性、证据准确性和语言效率，修正确认的退步，保留有效内容并说明取舍。交付当前稿件、简短修改及对比说明、待补文献或研究证据和下一步；同步更新工作事项，使另一智能体可从仓库通用入口接续，而无需重建会话历史。
