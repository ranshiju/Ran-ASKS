# 论文核心科学问题凝练

> `academic.manuscript_question` 的 `manuscript-question/general` capability。宿主 Agent 负责阅读、科学定位与措辞判断；shared 路由只派发规范。本文是核心科学问题凝练的单一维护源，论文评估与写作按需复用。

## 入口与范围

在仓库根目录运行：

```bash
python3 .scripts/route.py --capability manuscript-question
```

适用于从稿件提炼核心科学问题、核验用户提出的问题是否对应论文、调整科学概括层级和澄清核心概念。保持已有研究工作上下文，复用当前版本的有效阅读与已认可定位。功能完成于给出有稿件依据、概念清楚且简练的推荐问题及必要的研究范围说明；仅凝练问题时不自动评分贡献或修改论文。

入口不依赖特定智能体 UI：具备文件读取和命令执行能力的宿主均可按上述 CLI 获取规范；只支持文件指令的宿主可直接读取本规范，遵循仓库约定完成同一任务。Codex skill 是附加发现入口。所需材料由用户在自己的工作目录提供；本功能不依赖作者个人路径、聊天历史、外部创建工具或模型 API。

## 从稿件识别科学未知

先确定目标稿件与版本，读取摘要、引言、主要结果、结论以及支持主线的图表和必要方法/附录。已有有效阅读可以复用；摘要或旧回复不足以核验时，补读决定性证据。材料不足时明确候选问题及待核验部分，不以用户示例代替稿件依据。

提取能改变科学理解的关键未知：什么对象在什么条件下呈现何种关系、规律、机制、边界或能力限制。根据论文类型选择合适的问题，不强制所有论文都讨论机制、因果或标度。方法与基准论文也应说明其新增能力让什么原本难以回答的问题变得可检验。

核对实际改变的因素、观察量、比较基线及主要结果。若实验同时改变训练、表示与执行等多个环节，问题的归因对象应覆盖实际比较，或明确尚未分离的因素。区分总体性能与变化规律、相关观察与机制解释、模型本身能力与包含工具的系统表现。

科学问题应统摄论文的主要贡献，而不只是概括某张图或复述“构建数据—训练模型—执行测试”的操作。用主要结果反查：论文能对这句话提供什么有证据的新回答；若答不上，调整问题或说明稿件主线尚未成立。

## 选择科学概括层级

分别判断三个层次：

- **核心科学问题**：研究希望理解的较一般关系或未知。
- **本文切入点**：稿件实际研究的对象、模型或可控体系，以及它为何能探查上述问题。
- **已验证结论**：证据支持的对象范围、条件和结论强度。

科学问题可以适度宽于实验对象。例如，以算术任务研究数学推理问题是合理候选，前提是其研究变量与一般问题有实质联系，并明确本文以算术为切入点。采用更上位概念时检查它是否保留同一个科学未知，是否引入了本文完全未涉及的能力或因果含义。广义问题不意味着全文已经解决该领域的一般情形；贡献仍按实际证据范围回答。

只有必要时才把具体体系或限定条件放进问题句；其余用一句“本文以……为切入点，考察……”交代。避免把问题压缩成实验参数清单，也避免用宏大背景掩盖与本文结果无关的未知。

## 科学性、清晰性与精炼性

先确定科学含义，再压缩语言。推荐句应让领域读者辨认研究对象、关键未知以及必要的条件或比较关系；用专业且明确的概念保留科学抽象，不以口语化操作说明替代科学问题。

对关键术语检查：它在本文指什么，如何由研究设计或结果识别，是否暗含超出证据的主张。必要时在问题后给简短释义，而不是把所有定义塞进一句话。检查“更优”“敏感性”“可执行推理”等词是否明确指向比较量和行为；不能靠术语堆叠制造科学性。

例如，“下降得更慢”可以在讨论性能随复杂度变化时提升为“标度行为”，但只有实际研究了这一关系才适用；有限区间的经验趋势不等于普适或渐近标度律。专业术语的选择服务于准确表达，不把本例规定为所有论文的措辞模板。

问句保持开放。按证据选择“能否”“如何影响”“在何种条件下”等表达，不把尚待验证的机制、优越性或普适性写成问题的前提。结果存在正负差异或条件依赖时，让问题能够容纳这些答案。

## 交付与多轮协作

默认先给一条首选核心科学问题，再按需要给一句本文切入点及少量关键理由、概念释义或证据定位。存在实质不同的科学定位时才给备选，并说明取舍；不堆叠同义版本。首次核验应交代依据和证据边界，纯措辞迭代复用这些判断。

用户示例用于理解其期望的科学层次和表达风格；先核对其是否贴合稿件，再给独立判断。用户认可的问题作为后续讨论基线；新增证据或定位分歧才重新调整，不反复重启已解决的讨论。

用户同时要求贡献或评分时，转用[论文评估规范](manuscript-evaluation.md)，让每条贡献直接回答该问题或提供回答它所必需的能力。已认可的广义问题与较窄的实验贡献通过本文切入点连接，不为字面范围一致而机械缩窄问题，也不扩大结论。

实际改摘要或全文由相应写作能力负责，沿用已有定位确认约定与授权。用户只要求讨论时交付讨论结果；要求保存时写入指定项目目录。跨会话接续依据项目已有的状态或研究记录恢复，并核对稿件版本，不新建专用审批状态机。

交付前检查：问题是否指向科学未知而非技术步骤；概念是否足够清楚；概括层级是否合理；现有结果能否回答；措辞是否预设未经证实的结论；是否保持用户已认可的方向。
