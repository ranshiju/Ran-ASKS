# 论文评估：核心贡献与强调顺序

> `academic.manuscript_evaluation` 的 `manuscript-evaluation/general` capability。宿主 Agent 负责阅读、分类、评分与科学判断；shared 路由只派发规范，不计算语义评分，不调用 API 或独立评审。本文是评分与主线讨论的单一维护源，摘要优化与全文改进按需复用。

## 入口与范围

```bash
python3 .scripts/route.py --capability manuscript-evaluation
```

在当前 `research` 工作上下文内评估指定稿件的科学问题、核心贡献及其对审稿人的潜在说服力。适用于独立论文评估、贡献排序和改稿前定位；不代替 `manuscript-diagnosis` 的指定目录诊断流程，也不代替 `paper-impact` 的已发表论文第三方评价取证。评估本身不改稿、不自动摄入或投稿；只有用户要求保存报告时才在授权项目目录写入报告。

先确定稿件版本、学科、目标期刊或读者和用户已接受的定位；目标期刊未知时按相关领域读者暂评，明确此假设，不自行指定期刊。复用当前已完成的阅读和有效证据；独立评估应通读主文、图表与图注、结论和支持核心贡献的附录/补充材料，摘要流程至少读取其主张所依赖的这些部分。材料不全时列出覆盖范围，先评证据充分的贡献。

## 提炼科学问题与分类

先用一至两句话说明：现有认识或能力缺少什么，本文解决了哪一个具体问题。随后提取相互独立的贡献，写成“相对于已有工作，本文新增了什么认识或能力”，而非方法名、实验数量或章节目录。同一结果的多个指标、不同规模复现和一项方法的组成部件原则上合并，避免重复计分；若控制实验独立排除了重要解释，可作为独立贡献。

每条贡献选一个主类别，必要时加一个次类别。类别不预设高低，方法、数据或基准也可能比某个发现更重要。

| 类别 | 识别依据 |
|------|----------|
| 科学发现与机制 | 新规律、现象、机制解释、边界或反例改变了什么认识 |
| 理论与形式化 | 新定理、界限、证明或形式化框架解决了什么问题 |
| 方法与能力 | 新方法或组合带来了什么此前欠缺的能力、资源优势或可解范围 |
| 基准、数据与评估 | 新数据、控制设计或评价方式让什么问题首次可检验或更可靠地可比较 |
| 实验与应用验证 | 真实平台、留出预测或应用验证补足了哪类关键证据 |
| 资源与可复现性 | 开放工具、协议或资源如何使他人能够完成重要且原本困难的工作 |

“使用 Lean”“做了真实实验”等动作不自动构成贡献。尚未实现的设想列为待验证主张；一般局限或常规消融可以作为支撑证据，无需凑成贡献条目。

## 重要性评分：1–10 分

每条核心贡献给出重要性评分与一句明确理由。**重要性指：在所述贡献成立的条件下，它对核心科学问题和目标读者有多大实质价值，因而有多强的潜在审稿说服力。** 它不是录用概率、期刊档次或对作者工作的奖励。采用整数和分档判断，不用小数制造精度，也不把多个贡献相加成论文总分。

| 分数 | 判断锚点 | 证据充分时的强调建议 |
|------|----------|----------------------|
| 9–10 | 改变关键认识、突破重要瓶颈，或使重要的原本不可行任务成为可能；须说明与最近工作的实质差别 | 主线候选，优先进入标题、摘要核心句和引言贡献段 |
| 7–8 | 对领域明确问题作出实质推进，有清晰新增能力或解释价值 | 摘要重点，组织主要结果与关键比较 |
| 5–6 | 有用但增量或适用范围有限，主要补强已有认识或能力 | 次要贡献，按其对主线的作用安排篇幅 |
| 3–4 | 常规适配、重复验证或局部改进，独立科学意义较弱 | 支撑材料，通常不作为摘要头条 |
| 1–2 | 与核心问题关联很弱，或尚未辨认出超出现有工作的实质新增 | 降低强调，重新核查是否构成贡献 |

评分理由结合以下因素作整体判断，不机械加权：问题本身的重要程度；相对最近工作的新增程度；新增能力、认识或可复用价值；与目标读者的相关性。解释高分究竟改变了什么，以及限制其得更高分的条件。适用范围窄不自动低分，负结果、边界或反例也可具有高价值；贡献类别、数值增幅和实验规模均不能单独决定分数。

新颖性或重要性依赖关键文献比较时，定向核验最接近的一次来源；知识库文献经 Wiki/Graph 定位后回到 Raw。未核验时写“暂评”及缺口，必要时给有依据的区间；连贡献本身都无法确定时标为“待评”，说明所缺材料，不编造确定分值。跨稿件、跨期刊的分数只有在相同参照下才可比较。同档且依据不足以区分的贡献可以并列，1 分差异不视为显著差别。

## 证据强度与实际强调

重要性与证据强度分别展示，防止把“如果成立会很重要”写成“已经充分证明”。按所述主张的范围评证据，而不是按论文篇幅评证据：

- **强**：关键主张有直接、充分且可定位的证明或实验支撑，主要比较与必要控制相称。
- **中**：主张有直接支持，但对象范围、关键控制、统计或最近文献比较仍有限，应按已验证范围表述。
- **弱**：主要依赖间接观察或推断，关键替代解释、控制或比较缺失。
- **待核验**：材料缺失或尚未读到决定性证据；不等同于论文实际没有证据。

说明证据是稿件报告、原始记录复核还是独立复现，不能把读过论文写成重跑实验。每条贡献附源文件/章节/图表/页码定位，以及影响说服力的主要缺口或可能的审稿质疑。

在证据强度与目标读者相关性相近时，重要性越高，越值得优先强调。高重要性且证据强的贡献作为主线；高重要性但证据中等的贡献按已验证范围突出；高重要性但证据弱的贡献优先补证，当前摘要只采用被支持的较窄主张；低重要性但证据强的结果作为支撑。若缩小主张会改变价值，按缩小后的主张重新评分。评分高不授权提高结论强度。

## 交付及改稿前定位

先给核心科学问题，再给按重要性排序的贡献表，最后推荐一条科学主线和需要补证的优先事项。各列可为可读性合并，但保留以下信息：

| 核心贡献（含范围） | 主类别 | 重要性 /10 | 证据强度及定位 | 评分理由、主要缺口 | 强调建议 |
|------------------|--------|------------|----------------|------------------|----------|

强调建议应指出标题/摘要/引言/主结果/补充材料中的位置或补证动作，不能只有“高/中/低”。解释排序为何能帮助审稿人理解论文的实质进展，避免只输出分数。核查贡献是否重复、评分理由是否与分档一致、夸大的主张是否因高分被误置于首位。

摘要或全文落地前，先向用户展示“核心科学问题—贡献分类与评分—推荐主线”，让定位可供判断。用户明确要求先确认，或尚未解决的主线分歧会实质改变改稿时，等待定位确认；同时可继续阅读和证据核对。已有认可的定位或已授权自主改稿时，给出判断后继续，不新增逐阶段审批。单纯语言校正和格式调整无需重新评估；多轮修改仅更新受新增证据、目标期刊或主张变化影响的条目。

评估建议与实际改稿分开授权。用户只要求评估时完成上述交付即停止；转入写作后由相应摘要/全文能力负责源文件、diff、构建与版式验收，不把评分报告当作事实库或新的工作状态。
