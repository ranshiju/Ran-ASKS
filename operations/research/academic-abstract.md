# 学术论文摘要撰写与修改

> `artifact.write` 的 `academic-abstract` profile。宿主 Agent 负责科学判断、叙事与落笔；路由程序只派发规范，不调用模型、评价创新性或预测录用。本文是摘要方法的单一维护源，skill 仅提供发现与入口。

## 入口与工作模式

保持论文所在的 `research` 工作上下文，按项目约定恢复状态。根据当前请求判定模式，不因出现“摘要”就改文件：

- **讨论**：评价说服力、结构、措辞或比较证据；读取本规范和必要材料，给出判断、依据与推荐表述。用户问“能否送审/录用”时，分别评价摘要的编辑吸引力与全文的证据缺口，不作结果承诺。
- **起草**：从论文或用户提供的研究结果形成摘要，直接完成约定交付。
- **修改**：从用户指定或当前已确认的最新版本修改。“同意，落地”承接此前已接受但尚未写入的意见；先核对实际文件，保留已接受的关键结论和实验贡献。

实际起草或修改（包括交付候选英文段落）前调用：

```bash
python3 .scripts/route.py --capability write --capability-profile academic-abstract
```

同一连续写作回合已加载则复用。讨论无需为此进入落笔流程。涉及物理论文时按需组合 `operations/research/physics-manuscript-editing.md`；其他学科采用其适用的术语和论文规范。

## 从论文确定摘要主张

先读当前摘要、引言中的贡献定位、主要结果、结论和支持关键主张的图表或补充材料。不要仅凭旧摘要改写，也不要把整个领域综述变成写摘要的前置任务。

确定目标期刊、受众、语言及已知字数要求；优先采用用户明确要求。仅在确实影响交付而材料无法确定时补问。需要声称遵守期刊硬性限制时查其当前官方说明，不把惯常篇幅当成规定，不把未公开稿件传入检索请求。

为拟用核心句建立轻量“主张—证据”对应，可保留在工作上下文，无需固定表格或新增状态文件：

- 科学结论是什么，改变了什么认识或使什么任务成为可能；与标准对象、已有方法、工程实现的关系是什么。
- 来源定位在哪里，是解析证明、数值观察、已知目标态验证，还是真实实验的预测检验；材料未重跑或原始记录未复核时如实区分。
- 对象族、系统规模、局域窗口、资源条件、指标定义及比较基线是什么；哪些条件决定主张成立。
- 哪些新意有文献支持，哪些只是“使用了某方法”；首创、领先和优于已有方法等主张按需回查关键一次文献。

用户提供的论文是当前稿件主张的依据；库内文献事实仍按 Wiki/Graph 定位并回到 Raw 核验。过程日志、旧回复和研究记忆只恢复讨论脉络，不替代证据。

## 改稿前评估贡献与定位

实质性起草或修改前，先恢复最新认可的标题、核心科学问题、贡献评估和背景动机，并核对其对应的稿件与证据。已有有效结果直接复用；缺失、与稿件不符，或新增证据、目标与主张变化影响定位时，按需调用对应能力，仅更新受影响部分：

| 能力 | 为摘要提供的输入 | 需要补齐时的入口 |
|---|---|---|
| [核心科学问题](manuscript-question.md) | 摘要要回答的科学未知、本文切入点与范围 | `python3 .scripts/route.py --capability manuscript-question` |
| [核心贡献及评分](manuscript-evaluation.md) | 贡献排序、证据强度及推荐主线，决定内容取舍与强调顺序 | `python3 .scripts/route.py --capability manuscript-evaluation` |
| [背景与动机](manuscript-motivation.md) | 摘要用简短动机：为什么值得研究、已有进展为何不足 | `python3 .scripts/route.py --capability manuscript-motivation` |

首次形成定位时，按论文评估规范展示核心科学问题、贡献分类与重要性评分、证据强度及推荐主线，再形成摘要。高重要性且证据充分的贡献优先占据核心篇幅；支撑性贡献按论证需要进入，证据不足者明确补证需求或缩小主张。评分用于取舍，不写入摘要，也不机械决定句数。

主线确认、仅评估时的交付边界遵循论文评估规范：用户要求先确认或存在会实质改变稿件的定位分歧时等待；已认可定位或授权自主改稿时继续。单纯语言与格式校正不重做定位、评分或检索。三项能力的方法各自在原规范维护，摘要功能负责整合写作，不复制其规则或新增逐阶段审批。

## 形成科学主线

摘要以有力的动机直击主题，围绕核心科学问题组织核心贡献，以必要的方法和关键证据提供支撑，最后点明科学意义，并按需提出有依据的展望。整体语言简练有力且易读、逻辑清晰紧凑。

沿“动机 → 核心科学问题 → 核心科学贡献 → 必要证据 → 科学意义”形成连贯论证，按论文类型调整句序；相邻功能可合并，不机械拆成固定句数，也不直接拼接各功能的交付文字。

1. **首句有力地点出动机。** 用具体科学需求、瓶颈或认识缺口直击主题，让读者迅速理解为什么值得研究；优先直接易懂的表达，不用泛泛的重要性或密集术语开场。
2. **紧接核心科学问题。** 明确本文解决什么科学未知，动机与问题可合并表达，问题也不必写成问句。随后直接陈述核心发现及其推进的认识，让贡献成为摘要主体，避免研究流程或实验清单占据主线。
3. **方法交代本文实际贡献。** 仅保留使问题可研究、结论可检验的关键设计。本文构建或提出的方法、基准、框架，应使用准确的动作词体现，区别于使用现成工具；具体动词依实际工作与英文搭配选择。方法本身是贡献时说明新增能力，否则简要连接到发现。因果或机制解释须有相应证据。
4. **证据按论证需要取舍。** 可简要加入最有说服力的核心数据，不强制每篇摘要列数字。若比较方向、变化规律或成立条件已能具体支撑贡献，可不列精确数值；避免只有形容词的空泛结论。选择量化证据时保留指标和必要范围，省去不影响判断的型号、配置、数据规模及有效位数；先讲科学发现，再给数据支撑。
5. **结尾点明意义。** 说明发现带来的新认识、能力或研究方向，避免重复前文结论。展望可选，须从本文结果自然推出，不以空泛应用前景或未验证的普适能力拔高贡献。

保留决定结论成立的条件、平均与局部趋势的区别及重要反例，把边界直接融入发现；常规局限和细节解释放在正文，避免防御性表述挤占贡献。逐句选择准确、有信息量的动词，删除重复结论、空泛过渡和过长句中的次要信息；精简不能牺牲核心概念清晰性。优先使用直接的动词和清楚的主谓结构，减少抽象名词堆叠、含糊指代及多层从句；必要术语保留并就近说明，不以术语密度或生硬表达制造力度。

沿用已核验文献，新增实质性主张才补查。背景文献通常不在摘要中列引文，期刊另有要求时遵循其规定。

对于跨领域期刊，优先让读者理解“这项进展为什么值得关注”；具体评估目标期刊，不将一次 PRL 修改经验变成所有摘要的模板。

## 逐词逐句审阅：从读者理解反查科学表达

逐句读摘要，对承载概念、对象、条件、比较和评价的关键词追问其作用。目标是减少读者理解科学贡献所需的推断，并使措辞与证据相称；不用“更学术”的同义词替换代替判断，也不预设每句都必须修改。已有认可的科学主线约束局部改写，局部发现的实质问题也可促使重新安排贡献层级。

先用自己的话说出一句话实际表达了什么，再问它在整段中承担什么任务、读者可能怎样理解。按当前薄弱处选择下面的问题自检，不逐项要求用户回答，也不强制把所有检查展示成清单：

| 审阅对象 | 提问与反思 | 改进动作及预期效果 |
| --- | --- | --- |
| 首句与目标层级 | 点出的是具体科学瓶颈，还是泛泛的重要性？直接研究目标与更远的应用之间是否有证据连接？ | 先建立问题与本文贡献的直接联系，再交代应用意义，使动机有力且因果链完整。 |
| 动词、名词与指代 | 这个词表示什么操作或对象？是实际含义还是作者意图？删去修饰语会损失信息吗？是否可能被理解为另一种规模、最优性或通用性？ | 优先使用准确动作和具体对象；必要术语就近解释，已由定义包含的修饰可删，使读者无需猜测。日常词与专业词按实际清晰性选择。 |
| 条件与句子负担 | 一个条件是结论成立的前提、比较的控制变量，还是实现细节？一句话是否同时承担背景、方法、复杂度和结果？ | 保留改变主张真值或比较意义的条件；次要细节移正文，条件可后置或拆句，让主要结果先被读到。精简不等于一律删除限定。 |
| 贡献的层级与互补性 | 最强贡献有没有成为主句？整体与局部、规模与精度、理论与实验分别回答什么问题？某一项是否掩盖另一项？ | 并列保留重要且不同的结果，说明其证据角色；让支撑性结果服务核心推进，避免平铺功能清单或用局部优势替代整体结论。 |
| 数值与读者判断 | 读者知道这个数为何好、相对谁、在哪种任务和预算下吗？数值表达的是绝对质量、尺度趋势还是相对优势？ | 选择最能解释发现的数值或比较关系；必要时把倍数换成易读比例，核对分母、误差与平方误差、相对变化与百分点。既不堆数，也不把全部依据删成形容词。 |
| 比较对象与范围 | 方法名是否明确？相同预算与同一批数据是否混淆？单个基线被写成整个方法类别了吗？不同数据集的结果是否被接成同一项测试？ | 用直接语言说明实际控制条件、具体基线和指标，保留影响理解的数据集区别，使优势可解释且不外推。 |
| 评价词与结尾 | efficient、scalable、practical 等词分别承诺什么？结尾只是复述结果/列用途，还是说明核心进展使什么认识或能力成为可能？ | 选与核心贡献和证据相称的评价维度；以“核心进展 → 新增认识或能力 → 适用的科学意义”收束，不靠更强形容词或未验证应用拔高。 |

对一个关键问题，形成简短的“当前读法 → 问题及影响 → 推荐改法 → 收益与取舍”。优先给一个可直接使用的候选，确有不同科学侧重时才提供备选；用户提问是诊断入口，不自动表示必须按其假设改词。依据证据独立判断，也可以保留原句并解释原因。

局部改完必须回到整段重读：主线和贡献排序是否仍清楚，相邻句是否重复，指代、对象、资源条件及比较范围是否连续，核心方法是否在删减中消失，结尾是否比前文推进了一层意义。必要时合并或重组句子，而非机械拼接历次候选。验收看概念更明确、阅读负担更低、贡献更突出、比较更可解释及证据边界完整；字数减少、替换词数或“更强”的语气都不能单独证明改进。

## 比较优势与实验贡献

比较主张先明确任务、必要条件、基线及改善的指标或行为；改善幅度有助于判断核心贡献时，再给代表性数值：

- 相同目标、记录或预算与相同指标构成受控比较；不同文献的规模或数值只能提供背景，除非可比性已核实。
- 区分误差与平方误差、重叠与保真度、相对变化与百分点、固定预算误差与样本复杂度、单点优势与误差增长速率。一个较低误差点不能证明更慢的尺度增长；平方误差降低百倍不能改写成测量次数降低百倍。
- 优先突出有说服力的相关基线。对一个具体基线的优势不扩大为所有已有方法或整个方法家族；如果测量分配、先验或资源条件可能决定比较，核对已有配对检验，并明确其适用范围。
- 概括方法能力时用一般描述；报具体比较幅度时保留支撑它的系统、窗口或对象条件。局域误差优势不能代替全局重构优势。

真实实验有独立证据价值时，简要交代平台、验证对象和关键结果，突出在真实数据上预测或验证了什么；具体规模及验证细节按论证需要保留。量化规模时区分硬件总容量与实际使用的物理比特、通道、样本等数量；区分留出检验与训练拟合。

模拟与实验可相互补充：已知目标的模拟检验重构精度，实验检验现实噪声、数据或环境中的预测能力。分别保留指标和比较范围，不把模拟中的改善倍数接到实验上，也不把局域预测当作全局态认证。若实验对象简单或信号受噪声限制，说明它究竟支持哪种主张；表述力度与实验证据相匹配。

篇幅受限时先删重复背景、重复结论及低价值实现细节，再压缩句子。对已确认的重要模拟优势和真实实验贡献，应优先保留互补的证据角色；确需删除其中一项时说明取舍，不为迁就当前分页而静默删掉科学卖点。

## 多轮修改与交付

用户要求“更强”时，先分清是结论被数字淹没、方法与能力脱节、比较或实验结果被弱化，还是证据本身不足。优先调整信息层级、结果动词和比较条件；形容词升级不能弥补证据缺口。当前证据支持的强表述与需要新增实验才能支持的主张要明确区分。

在一轮内整合已接受意见后再生成完整交付，避免每改一个词就反复编译。讨论时可给推荐句而不改文件；执行修改时保留用户未要求变更的正文、数据、图表及引用。

持续讨论复用论文工作区的状态、记忆和一份当前讨论记录，按主题保存有实质作用的问题、理由、候选、取舍及下一步。区分用户偏好、Agent 建议、已采纳、已写入和已验证；新意见对旧意见是补充、限定还是替代应说明。用户要求先讨论时只更新这些记录，明确授权后再一次性整合改稿。接续先核对当前版本和最新有效决定，不把完整聊天复制成提示词或为每个词增加状态项。

作者报告新结果时，区分作者明确确认的事实、已查看的数据及尚未提供的指标；可以据其明确陈述形成修改稿并在修订记录中标明依据，不能自动补出未说明的精度、预算、重复次数或比较优势。扩大规模或结论范围后，核对标题、摘要、正文、图表与补充材料是否仍一致；旧图保留原测试范围，待补内容记录具体位置，已获授权且证据充分的改动继续完成。

- 文本交付：提供当前推荐摘要及关键变化；报告字数时注明统计口径，准确命名当前版本。
- 文件交付：完整稿沿用[主文档命名与版本约定](manuscript-improvement.md#主文档命名与版本)，保留上一版并生成 diff；用户明确指定版本策略时按其要求执行。独立摘要候选标明所属稿件版本，不凭修改时间猜 canonical 版本。
- LaTeX：沿用原工程及依赖，至少编译两遍或确认自动构建完成所需遍数；检查未定义引用/citation、重复标签、溢出与浮动图警告。先用结构化检查，再对受影响页面做视觉抽检。区分既有与新增问题；无法编译时保留源文件并说明原因。
- 分页变化如实报告。不要用未经授权的字号、页边距或正文压缩换取固定页数。当前任务只改摘要时，额外发现的论文问题在交付中提示，不擅自扩大修改范围。

交付前完整通读摘要，按“通顺易读、简练有力、逻辑清晰紧凑、重点突出”检查：首句能否直击主题，问题是否得到贡献回应，证据是否各有作用，结尾是否推进意义；删去重复信息、空泛过渡和无助于判断的数据细节。再与正文、最新认可的标题及上一版对照，确认关键主张准确、重要贡献未在精简中丢失，修改确实改善了整段表达，而非仅替换局部词语。

总结讨论时，按“提问发现了什么 → 为什么需要改 → 如何改 → 获得什么、保留什么限制”凝练可迁移判断，而不是只列替换词对。通用规范保存方法，具体稿件的句子、数值与版本留在项目。构建检查、Agent 的文本对比和目标读者的理解效果分别报告；未经独立评估，不把一次协作修改称为已验证的普遍阅读或投稿收益。
