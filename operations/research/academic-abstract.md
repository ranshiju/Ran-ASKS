# 学术论文摘要撰写与修改

> `artifact.write` 的 `academic-abstract` profile。宿主 Agent 负责科学判断、叙事与落笔；路由程序只派发规范，不调用模型、评价创新性或预测录用。本文是摘要方法的单一维护源，skill 仅提供发现与入口。

## 入口与工作模式

保持论文所在的 `research` 工作上下文，按项目约定恢复状态。根据当前请求判定模式，不因出现“摘要”就改文件：

- **讨论**：评价说服力、结构、措辞或比较证据；读取本规范和必要材料，给出判断、依据与推荐表述。用户问“能否送审/录用”时，分别评价摘要的编辑吸引力与全文的证据缺口，不作结果承诺。
- **起草**：从论文或用户提供的研究结果形成摘要，直接完成约定交付。
- **修改**：从用户指定或当前已确认的最新版本修改。“同意，落地”承接此前已接受但尚未写入的意见；先核对实际文件，保留已接受的关键结论和实验贡献。

实际起草或修改（包括交付候选英文段落）前调用：

```bash
python3 .scripts/route.py --capability write --capability-profile academic-abstract
```

同一连续写作回合已加载则复用。讨论无需为此进入落笔流程。涉及物理论文时按需组合 `operations/research/physics-manuscript-editing.md`；其他学科采用其适用的术语和论文规范。

## 从论文确定摘要主张

先读当前摘要、引言中的贡献定位、主要结果、结论和支持关键主张的图表或补充材料。不要仅凭旧摘要改写，也不要把整个领域综述变成写摘要的前置任务。

确定目标期刊、受众、语言及已知字数要求；优先采用用户明确要求。仅在确实影响交付而材料无法确定时补问。需要声称遵守期刊硬性限制时查其当前官方说明，不把惯常篇幅当成规定，不把未公开稿件传入检索请求。

为拟用核心句建立轻量“主张—证据”对应，可保留在工作上下文，无需固定表格或新增状态文件：

- 科学结论是什么，改变了什么认识或使什么任务成为可能；与标准对象、已有方法、工程实现的关系是什么。
- 来源定位在哪里，是解析证明、数值观察、已知目标态验证，还是真实实验的预测检验；材料未重跑或原始记录未复核时如实区分。
- 对象族、系统规模、局域窗口、资源条件、指标定义及比较基线是什么；哪些条件决定主张成立。
- 哪些新意有文献支持，哪些只是“使用了某方法”；首创、领先和优于已有方法等主张按需回查关键一次文献。

用户提供的论文是当前稿件主张的依据；库内文献事实仍按 Wiki/Graph 定位并回到 Raw 核验。过程日志、旧回复和研究记忆只恢复讨论脉络，不替代证据。

## 形成科学主线

默认沿“问题与障碍 → 方法带来的能力 → 科学结论 → 代表性证据 → 应用或实验意义”推进；根据理论、计算、实验或方法论文调整权重，不强制固定句数，也不要求每篇都同时具备模拟与真机。

1. **动机说清矛盾。** 用具体科学需求与现有瓶颈开场，避免只说重要、迫切。把一般问题的困难与结构假设下可解的范围分清。
2. **方法说明因果作用。** 解释表示、训练、算法或实验设计如何产生新增能力。已有方法的组合可以有价值，但“用了 A 和 B”本身不等于创新。
3. **科学结论先于细节数据。** 在精确小数、误差条和运行参数之前，先说得到什么能力、尺度行为、机制或资源认识。“达到某精度”是结果；“在何种条件下，系统变大仍能保持何种信息或能力”才进一步解释科学意义。头条规模可以作为结论的一部分，避免机械禁止首句出现数字。
4. **数据各有论证作用。** 选择最能支持主线的规模、精度、比较幅度或实验结果，保留指标名称和必要限定，减少不影响判断的有效位数。数值不能代替结论，也不能只留下形容词而没有支撑。
5. **意义推进认识。** 说明结果对可行表征任务、资源需求、机制理解或应用边界的后果。结尾提供这一层认识，不重复上一句，也不凭空扩展到未研究的普适能力。

对于跨领域期刊，优先让读者理解“这项进展为什么值得关注”；具体评估目标期刊，不将一次 PRL 修改经验变成所有摘要的模板。

## 比较优势与实验贡献

比较主张尽量给出“在什么任务和条件下，相比哪个基线，以何种指标改善多少”：

- 相同目标、记录或预算与相同指标构成受控比较；不同文献的规模或数值只能提供背景，除非可比性已核实。
- 区分误差与平方误差、重叠与保真度、相对变化与百分点、固定预算误差与样本复杂度、单点优势与误差增长速率。一个较低误差点不能证明更慢的尺度增长；平方误差降低百倍不能改写成测量次数降低百倍。
- 优先突出有说服力的相关基线。对一个具体基线的优势不扩大为所有已有方法或整个方法家族；如果测量分配、先验或资源条件可能决定比较，核对已有配对检验，并明确其适用范围。
- 概括方法能力时用一般描述；报具体比较幅度时保留支撑它的系统、窗口或对象条件。局域误差优势不能代替全局重构优势。

真实实验有独立证据价值时，应写出**实验平台、实际使用的对象规模、验证方式和取得的结果**。由“测试了方法”推进到“在真实数据上预测了什么、相对谁表现如何”。区分硬件总容量与实际使用的物理比特、通道、样本等数量；明确留出检验与训练拟合的差别。

模拟与实验可相互补充：已知目标的模拟检验重构精度，实验检验现实噪声、数据或环境中的预测能力。分别保留指标和比较范围，不把模拟中的改善倍数接到实验上，也不把局域预测当作全局态认证。若实验对象简单或信号受噪声限制，说明它究竟支持哪种主张；表述力度与实验证据相匹配。

篇幅受限时先删重复背景、重复结论及低价值实现细节，再压缩句子。对已确认的重要模拟优势和真实实验贡献，应优先保留互补的证据角色；确需删除其中一项时说明取舍，不为迁就当前分页而静默删掉科学卖点。

## 多轮修改与交付

用户要求“更强”时，先分清是结论被数字淹没、方法与能力脱节、比较或实验结果被弱化，还是证据本身不足。优先调整信息层级、结果动词和比较条件；形容词升级不能弥补证据缺口。当前证据支持的强表述与需要新增实验才能支持的主张要明确区分。

在一轮内整合已接受意见后再生成完整交付，避免每改一个词就反复编译。讨论时可给推荐句而不改文件；执行修改时保留用户未要求变更的正文、数据、图表及引用。

- 文本交付：提供当前推荐摘要及关键变化；报告字数时注明统计口径，准确命名当前版本。
- 文件交付：遵循已有版本约定，保留上一版并生成 diff；若用户明确要求原位更新或指定版本策略，按其要求执行。不要凭文件修改时间猜 canonical 版本。
- LaTeX：沿用原工程及依赖，至少编译两遍或确认自动构建完成所需遍数；检查未定义引用/citation、重复标签、溢出与浮动图警告。先用结构化检查，再对受影响页面做视觉抽检。区分既有与新增问题；无法编译时保留源文件并说明原因。
- 分页变化如实报告。不要用未经授权的字号、页边距或正文压缩换取固定页数。当前任务只改摘要时，额外发现的论文问题在交付中提示，不擅自扩大修改范围。

最后从两种读者视角自检：编辑能否迅速识别问题、新增能力和广泛意义；审稿人能否将每个强主张对应到正确的对象、指标和证据。通过的是摘要的一致性与交付检查，不是对送审或录用的保证。
