# 学术论文引言撰写与修改

> `academic.manuscript_introduction` 的 `manuscript-introduction/general` capability。宿主 Agent 负责阅读、文献判断和写作，shared 路由只组合本规范与共享落笔约定。本文是完整引言方法的单一维护源，全文改进流程按需复用。

## 入口与范围

在仓库根目录运行：

```bash
python3 .scripts/route.py --capability manuscript-introduction
```

保持论文所在的 research 工作上下文；入口已组合 `WRITE.md` 共享约定，无需重复加载通用 academic profile。其他智能体可运行同一 CLI，或直接读取本规范及共享写作章节。方法与入口保存在仓库，论文实例留在用户项目，不依赖作者个人路径、会话记忆或模型 API。

- **讨论**：检查引言结构、论证或候选措辞，给出建议，不自动改文件。
- **起草或应用**：交付一版带引用的完整引言，附简短组织说明和必要证据缺口；保存候选到稿件项目。
- **修改或替换**：在用户授权范围内按[主文档命名与版本约定](manuscript-improvement.md#主文档命名与版本)修改；“应用功能”默认交付候选，明确要求替换引言或已授权整篇改稿时直接落实。

单独背景动机使用 [manuscript-motivation](manuscript-motivation.md)；本功能承接完整引言中的文献定位、本文切入点与贡献论证，不自动扩为全文修改。

## 从已有稿件与定位出发

先确认当前稿件、目标期刊、语言与篇幅，以及最新认可的标题、科学问题、贡献和摘要。已有稿件时，必须以其为基础或参考：读原引言及其引用，结合摘要、方法、主要结果、图表、讨论和必要补充材料，辨认有效论证、缺口与偏离最新主线的内容。保留仍成立的科学内容、必要引用和术语；按需要局部修改或重新组织，不默认重写优于原稿，也不为保留原句延续错误主张。无稿件时依据用户研究材料起草，缺失事实明确标出。

复用未变材料的有效阅读与已认可判断；已有措辞和评分不是事实证据，关键主张仍须能定位到稿件或文献。定位缺失、证据或目标变化时，按需补齐：

| 输入 | 对引言的作用 | 能力 |
|---|---|---|
| 核心科学问题 | 明确全文要回答的未知及本文切入点 | [manuscript-question](manuscript-question.md) |
| 核心贡献及评分 | 决定论证重点，结合证据强度确定主张与强调顺序 | [manuscript-evaluation](manuscript-evaluation.md) |
| 背景与动机 | 提供研究必要性、已有进展与不足的论证素材 | [manuscript-motivation](manuscript-motivation.md) |

按各能力的同名 `--capability` 入口加载所缺规范；不为每次改稿重跑全部功能。沿用贡献评估的定位确认约定，已有认可定位直接继续。标题与摘要约束主线一致性，完整引言仍根据全文证据独立组织，不机械扩写摘要。

## 组织完整论证

让读者理解“问题为何重要、已有研究解决到哪里、本文新增了什么科学认识或能力”。以下是论证任务，不是固定段落模板；篇幅、顺序和段数按领域、期刊与论文内容调整：

1. **背景与动机**：说明核心问题为何值得研究、已有进展为何仍不足以回答。将背景动机功能的素材融入全文，保持科学张力和概念清晰，避免泛泛重要性与重复意义。
2. **已有研究与关键未知**：围绕问题组织最相关工作及其真实进展，明确本文承接什么、进一步回答什么；不按作者逐篇罗列。背景可与文献定位交织；已有独立 Related Work 时合理分工。
3. **本文切入点**：说明研究对象和设计为何能探查上述未知，交代理解贡献必需的方法概念。区分一般科学问题与本文已验证范围，将具体流程、超参数和实现细节留给方法部分。
4. **核心贡献与意义**：用科学结论回应前文未知，先突出重要且证据充分的贡献，再说明必要的方法或验证贡献。代表性结果按论证需要选用，评分不写入正文；不强制列贡献清单，不把实验目录、技术组件或摘要数字的重复当作贡献段。

方法、基准或实验验证本身构成核心贡献时，明确其新增能力；机制解释须与证据相称。支持性结果说明其补足了哪类证据。核心术语保持一致，涉及新概念时在首次实质使用处简要解释。结尾说明结果推进了什么认识或能力，章节导航仅在有助阅读或期刊要求时加入。

## 文献与证据

复用背景动机规范中的来源核验方法，综合原稿、已有引用、领域知识、知识库和必要网络来源。已有相关核验结果直接复用；新增论断或确有缺口时定向检索。公开检索只携带公开线索，不上传未公开稿件；知识库事实回溯 Raw，写作不自动摄入。

主动考虑相关顶刊或领域权威论文支撑背景与意义，同时保留最接近的专业文献界定实质推进。声望不扩大证据范围；邻近领域成果、模型规模效应等不能直接当成本文对象或自变量上的证据。明确区分尚未研究、证据范围有限、结论不一致与缺少可靠测量，避免绝对空白或未经核验的首创主张。

引用应支持紧邻论断。复用已有引用键，核验新增题录、年份和 DOI/稳定链接并去重；区分预印本与正式版本。只读摘要时采用其直接支持的事实，具体方法差异需核验正文。旧稿引用也须与修改后的句子重新匹配；无法核验时缩小表述或注明缺口。

## 回查与交付

交付前核对：每段是否推进同一主线，未知是否被贡献回应，贡献是否能在正文定位到证据，标题、摘要与引言的术语和范围是否一致。删去重复背景、过早技术展开和无依据的宣传。

默认提供一版完整引言及简短修改说明，必要时另列待核验事项；英文稿以英文质量为准，中文讨论可给中文稿，用户需要时提供对应译文。候选稿保存到用户项目，标明参考原稿与定位版本；新增引用提供已核验题录和明确引用键。只交付候选文本时检查引用键与内容完整性；替换源文件时交付 diff，并复用[摘要规范](academic-abstract.md)的构建、引用/标签和受影响页面检查。检查通过不等于科学结论经独立复现。

**最后一步：与原稿对比验收。** 有原稿时，以指定原稿为基线；多轮修改同时核对上一版，避免只比较最近版本而丢失原有优点。围绕问题提出的直接性、科学主线与贡献表达、文献定位与证据准确性、语言效率，指出具体改进及可能损失。原文更好的部分予以保留或恢复，确认的退步先修正并复查受影响项，再交付。没有明确收益的改写不强行采用；存在无法消除的取舍时如实说明，不预设新版全面更好。交付附简短对比结论及关键文本依据，不强制评分或长表格；无原稿时明确比较基线缺失，按研究材料与目标检查，不虚构对比。
