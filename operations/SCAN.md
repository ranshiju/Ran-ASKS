# Scan（扫描摄入）操作规范


---

## 触发方式

用户说"扫描 WikiRan""摄入所有新文件""扫描所有子项目"等。

## 执行步骤

1. **遍历 raw/**：递归遍历四个子项目的 `raw/` 目录，列出所有文件及其修改时间
2. **LLM 语义分组**：对同一子目录下的文件名列表，使用 LLM 进行版本分组判定：
   - 将文件列表提交给 LLM，判断哪些是同一文档的不同版本，归入同一组
   - LLM 输出每组的基础名（base_name），如"十五五规划""科研经费管理办法"
   - 归入同一组后，取修改时间最新的文件作为该组的**当期版本**
   - 分组逻辑示例：
     - `十五五规划V1.pdf` + `十五五规划V2.pdf` → 同组，base_name="十五五规划"
     - `科研经费管理办法.docx` + `科研经费管理办法（修订版）.docx` → 同组
     - `张三述职报告.docx` + `李四述职报告.docx` → 不同组（不同人）
     - `十四五总结.docx` + `十四五规划.docx` → 不同组（不同文档）
3. **对比 log.md**：读取各子项目的 `wiki/log.md`，提取所有已摄入的 base_name
   - 对每个 base_name，检查其对应文件的最新修改时间是否晚于 log.md 中该 base_name 的摄入时间
   - 如果 base_name 在 log.md 中无记录 → 标记为 **新文件**
   - 如果 base_name 在 log.md 中有记录，且当期版本修改时间 > 摄入时间 → 标记为 **更新**
   - 如果 base_name 在 log.md 中有记录，且当期版本修改时间 ≤ 摄入时间 → 跳过
4. **按子项目分组处理**：在每组内按类型处理：
   - **新文件**：按标准 Ingest 流程（见 `operations/INGEST.md`），创建新的 wiki 页面
   - **更新**：读取已有 wiki 页面，用当期版本的内容增量更新，保留人工修正的部分
5. **更新索引和日志**：每完成一个子项目，更新其 `index.md` 和 `log.md`
   - `log.md` 中更新操作标记为 `update | base_name (旧版本 → 新版本)`
6. **输出扫描报告**：

```markdown
## 扫描报告 (YYYY-MM-DD)

| 子项目 | 子目录 | 文件名 | 操作 | 说明 |
|--------|--------|--------|------|------|
| admin | policies | 十五五规划V2.pdf | 更新 | V1→V2，修改时间晚于摄入时间 |
| admin | policies | 科研经费管理办法.docx | 新文件 | 首次摄入 |
| admin | meetings | 2025-12会议纪要.docx | 跳过 | 已摄入，未变化 |
```

## 版本分组判定原则（LLM 在步骤 2 中遵循）

- 核心主题相同，仅版本号不同 → 同组
- 核心主题相同，仅日期/年份不同 → 同组
- 核心主题相同，仅状态标记不同（征求意见稿/正式稿/修订版）→ 同组
- 核心主题相同，仅括号内标注不同 → 同组
- 核心主题不同 → 不同组
- 共享部分关键词但指向不同实体 → 不同组

## 重要约束

- 如果同时有多个子项目有新文件，优先处理 admin → academic → teaching → business
- 如果某个子项目有超过 5 个新文件，分批处理，每批完成后告知用户进度
- 扫描前先向用户报告发现的文件列表和分组结果，确认后再开始摄入
- 对于"更新"类型的文件，覆盖 wiki 页面时保留人工手动添加的 `related` 链接和注释

## inbox/ 扩展

Scan 执行时，同时检查 `inbox/` 目录：
- 如果 `inbox/` 中有文件 → 在扫描报告中额外列出，提醒用户处理
- `inbox/` 中的文件不计入各子项目的扫描统计
