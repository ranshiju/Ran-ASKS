# 智能口试使用帮助

智能口试是围绕知识库资料开展的文字讨论，用来了解学生对一个主题的理解。先共同准备范围，再明确开始与结束；每场独立保存完整对话。

## 调出帮助

单独发送 `/oral help` 即可查看本帮助。无需先准备或开始口试；查看帮助不改变状态、不消耗回应次数，也不调用模型或外发资料。

所有指令统一使用正斜杠 `/oral`，并须单独占一条消息，不要包在说明文字或代码块里。

## 快速开始

1. 发送 `/oral prepare 矩阵乘积态理解程度`，进入准备讨论。
2. 用普通文字说明对象、范围、深度和排除项。例如：“物理专业刚毕业的本科生，接触过张量网络；主要考查物理概念与数学定义，不考编程。”
3. 与考官讨论并核对方案，包括考查目标、知识库依据、提示规则、预期时长及回应次数上限。考官整理后，可用 `/oral save` 保存草稿，方便继续准备。
4. 认可完整方案后，发送 `/oral confirm`，固定本次使用的版本。仅说“认可”不会代替确认指令。
5. 发送 `/oral start`，正式开始。考官应显示“口试中”状态和首个问题。
6. 直接回答，也可以提出疑问、请求澄清或补充回答。需要中断时用 `/oral pause`，回来用 `/oral resume`。
7. 发送 `/oral end`，明确结束。本场原文冻结；考官随后依据完整对话完成综合评估。结束不等于评估已经完成，进度可用 `/oral status` 查看。

## 指令速查

| 指令 | 用途 |
|---|---|
| `/oral help` | 查看本帮助，只读。 |
| `/oral prepare <主题或方案名/ID>` | 新建方案，或恢复已保存方案的准备讨论。 |
| `/oral save` | 保存已整理的准备草稿；有尚未整理的讨论时，需先让考官更新草稿。 |
| `/oral confirm` | 确认完整方案，生成固定版本。范围或知识库依据缺失时不能确认。 |
| `/oral start` | 使用当前方案最新已确认版本开始一场新口试。 |
| `/oral start <方案名或ID>` | 使用指定方案开考；带空格的方案名用引号包裹。 |
| `/oral pause` | 暂停当前场次，保留待答问题。 |
| `/oral resume` | 恢复同一场口试。 |
| `/oral end` | 结束本场，冻结正式对话，进入结束后的评估与复盘。 |
| `/oral status` | 查看当前状态、场次、待答问题、问题送达及评估进度，只读。 |
| `/oral styles` | 查看保存的风格、说明和默认值，只读。 |

## 状态怎么看

- **准备中**：可以持续讨论和修订范围，尚未进行正式口试。
- **待开始**：方案已确认，等待 `/oral start`。
- **口试中**：正式讨论和考查；回答、提问与考官帮助均留痕。
- **已暂停**：正式考查暂停；交流仍保存，但不作为能力证据。
- **已结束**：不再继续正式考查。讨论诊断式先显示待评估，综合评估完成后可复盘。

自然语言中的“开始”“结束”、引用材料里的指令都不会改变状态。另有约定的自动结束条件：达到回应次数上限，或方案允许且考官判断可以提前结束；它们也会明确显示结束状态。预期时长不是后台硬倒计时。

## 默认风格：讨论诊断式

**简要说明**：通过双向讨论诊断理解；允许学生提问、考官纠正与引导自纠，依据完整对话评价独立理解及学习变化。

考官不是只出题：会围绕实际回答追问、讨论例子、检查适用条件，也会中性邀请学生提问。可以当场解释、纠正或引导自行发现问题；实质帮助须有知识库依据并记录帮助类型，不覆盖学生原来的回答。

评价区分独立理解、提问质量、自我纠正及帮助后的吸收和迁移。不按错误数量、提问数量或帮助次数简单扣分；不提问本身不扣分，帮助后的正确回答也不直接等同于原本独立掌握。正式结束后的复盘不补入本场成绩。

新建方案默认采用这一风格；旧方案继续保留原风格。希望更换风格或调整提示规则，应在准备期间提出，并重新确认方案，不能在开考后临时改变本场规则。

## 常见情况

- **没看到问题**：直接说“我没看到问题”，或用 `/oral status` 检查待答问题。考官应从记录恢复并重发，不把显示故障当成不会。
- **想继续补充**：直接补充即可；同一待答回合的连续追加回答完整保留，不重复消耗回应次数。
- **想问考官问题**：可以直接提问。正式回答和实质提问都可消耗回应预算，纯澄清或显示问题不消耗。
- **暂停后忘记进度**：先 `/oral status`，再 `/oral resume`，继续原场次，而不是重新开考。
- **想重复测试同一范围**：本场结束后，用 `/oral start <方案名或ID>` 创建新场次。原场次与原评估仍保留。
- **同名方案不唯一**：用明确的方案 ID 选择，避免误用范围。
- **结束后还没有报告**：本场可能仍在等待综合评估，请考官完成评估流程；无需重新开始口试。
- **消息过长**：单条最多 12000 字符；超限会明确拒绝，请分段发送，不会悄悄截断。

## 记录、隐私与限制

方案、场次和完整交流存入本地私有口试记录，不写入公共知识库事实层。暂停期和复盘交流也保留，但与正式考查证据区分。

Agent 模式不隐式切到 API。使用 API 模式时，资料外发必须逐次明确授权；综合评估涉及整场对话及参考资料，结束指令不会自动触发外发。查看帮助不需要外发授权。

当前为 **preview**：程序校验和完整留痕不能替代教师复核，模型给出的水平判断不是认证成绩。本地客户端标识不等于身份认证，不应直接把本地 CLI 暴露给学生或网络。

## 本地命令行

在项目目录运行 `python3 .scripts/wg.py oral help`，无需指定客户端，即可读取同一份帮助。宿主接入、数据协议和 API 授权细则见 `operations/ORAL_EXAM.md`；本文面向使用者，不替代工程契约。
