# Write（写作）操作规范

> `write` 是按需调用的**落笔能力**：使用可回溯事实与当前工作上下文生成文稿。它可以服务于独立办公写作，也可以作为 `research` 等持续工作状态中的组合能力；写作产物不自动成为知识库事实。智能体能力定义见 `agents/writer/AGENT.md`，其流程须与本规范一致。

---

## 触发与任务判定

用户要求撰写、准备、起草、生成、改写、压缩或排版以下材料时，路由为 `write`：

- 行政发言稿、讲稿、汇报、通知、请示、报告等公文；
- 学术简历、个人简介、项目申报辅助材料、合作交流材料、会议介绍等专业材料；
- 用户明确指定的 Markdown、Word、PDF、PPT 文字内容或版式文档。

研究论文仍以 `research` 作为持续工作状态。Agent 真正开始起草、改写或润色论文正文时，在该状态内调用 `write` 的 academic profile；讨论研究问题、核对数据和运行实验时继续保持 `research`，无需加载写作能力。

先判定工作模式，而非机械依赖单个触发词：

| 模式 | 判定信号 | 行为 |
|------|----------|------|
| 讨论（`discuss`） | 仅讨论选题、结构、措辞、材料是否充分，或明确说“先讨论/先列提纲” | 收集素材、给结构或风险建议；不生成完整正式稿 |
| 起草（`draft`） | 明确要求交付成品，如“准备一份”“写一页 Word”“生成/起草/出稿/正式写”，并给出文体或用途 | 直接执行起草；无需再要求重复确认 |
| 修改（`modify`） | 指向已有文稿并要求调整 | 读原稿、定向修改、复验 |

### 最小必要澄清

仅当下列缺口会实质改变内容或造成高风险时提问：文体/用途不明、受众不明、关键期限或署名不明、所需事实无法从用户或知识库确认。其余参数按合理默认值执行，并在交付时说明。

用户已明确目标格式（例如“一页 Word”）即视为该格式的生成授权；不得以“先出 Markdown、再确认 Word”阻断交付。

## 总体原则

1. **事实先于修辞**：所有具体履历、数字、项目、头衔、机构、时间和成果须能回溯用户提供材料或知识库来源。
2. **表述强度匹配证据**：直接事实可陈述；跨事实概括须保守限定；无证据的能力、身份、影响或政策主张不得写入。
3. **用途决定结构**：同一材料针对简历、申报、发言或对外传播，应按受众、篇幅和风险重组，不机械拼贴原始履历。
4. **格式是交付的一部分**：用户指定 Word/PDF、页数、纸张、字体或版式时，须实际生成并验证，不只提供文本。
5. **最小充分读取**：优先读取最权威、最接近主题的来源；不为写一份文稿做无关全库扫描。
6. **不回写事实**：写作推导、措辞与外部材料不自动摄入；只有用户明确要求“摄入”时才转入 Ingest。

## 共享落笔约定（可组合能力）

本节适用于所有文体，也是其他工作状态调用 `write` 时的最小共享风格包。

1. **正面说明作用与范围**：优先写清本文、文稿或系统做了什么，产生了什么可检查产物，以及证据覆盖哪些对象、条件和时间范围。
2. **用范围限定表达科学边界**：必要边界写成 evaluated scope、适用条件、已验证对象和后续验证层。让边界直接界定当前主张，避免用连续的否定式句子组织防御。
3. **保留有信息量的边界事实**：真实零计数、明确弃权、排除状态、回滚行为和下降趋势均按事实呈现；它们属于结果与机制，而非修辞性防御。
4. **符号大小写约定**：一般以大写拉丁字母表示总数、集合规模或全局量，以对应小写字母表示第几个对象、步骤索引或局部计数。例如，$T$ 表示总步数、$t$ 表示第 $t$ 步，$N$ 表示总样本数、$n(t)$ 表示第 $t$ 步的局部计数。
5. **定义优先且全文一致**：符号在首次实质使用前定义；领域公认惯例、标准常数和既有核心记号可优先于上述一般约定，但选定后保持全文一致。

## 事实与主张控制

起草前为关键句建立轻量“事实—表述”账本（可在工作上下文或交付说明中简述，无需固定落盘）：

| 等级 | 可以写什么 | 写法要求 |
|------|------------|----------|
| A：直接事实 | 任职、论文数量、项目、奖项、访问经历、出版物、日期等 | 忠实复述，保留必要限定与时间 |
| B：保守概括 | 由多项 A 类事实支持的经验或能力 | 使用“具备…经验”“可支持…”“基于…经历”等限定，不扩大为资质认证 |
| C：无充分证据 | 未记录的组织运营、政策制定、国际治理、语言能力、影响力等 | 不写；必要时向用户索取材料或显式标为待补 |

### 高风险表述

以下内容必须逐项核验，不能由相邻经历自动推导：

- 国际组织任职/运营管理、政府或国际科技治理规则制定；
- 涉密、财务、法律、伦理合规认证或正式授权；
- 排名、全球影响、唯一/首创、获奖、媒体报道等比较性结论；
- 他人身份、合作关系、未公开项目和个人敏感信息。

会议纪要、语音识别记录等低置信来源只可作过程性参考；除非用户明确要求，不应作为对外材料中唯一的权威依据。

## 起草工作流

### 0. 建立交付契约

确认或合理推定：用途与受众、文体、语言、篇幅/页数、目标格式、交付路径、是否需要模板或署名。用户未指定文件名时，使用 `projects/<主题>/<文体>-YYYYMMDD.<ext>`；短期临时文件可置于 `projects/` 根目录。

### 1. 汇总与检索证据

1. 读取用户提供原稿、附件或指定材料；
2. 按主题查询最权威的 wiki/raw 来源（行政事实优先 `admin/`，科研事实优先 `academic/`）；
3. 记录关键事实、来源和置信度，识别缺口与高风险主张；
4. 对模板型材料优先复用已有格式，不擅自改写用户的固定名称、日期、文号或数据。

### 2. 选择结构与风格

- 发言稿、公文：读取对应 `agents/writer/templates/` 模板与 `memory/MEMORY.md` 风格规则；
- 简历、个人简介、申报/合作材料：采用“定位—代表成果—相关经历—能力/贡献”结构，优先展示与目标岗位或场景直接相关的证据；
- 学术论文正文：保持 `research` 工作状态，调用 academic write profile，并同时应用 `operations/research/physics-manuscript-editing.md` 等相应学科写作 overlay。

### 3. 形成内容稿

- 先完成结构化内容，再压缩到用户要求的字数、页数或时长；
- 每个原则性或能力性结论至少由一个具体事实锚定；
- 对 B 类概括保留限定词，对 C 类主张删除或标记待补；
- 默认创建可编辑源稿（Markdown 或文本）；若用户只需 Word，可同时直接生成 Word，不必先征求格式确认。

### 4. 生成目标文件

| 用户要求 | 必做交付 |
|----------|----------|
| 未指定格式 | Markdown 源稿，落于 `projects/` |
| Word / `.docx` | 生成可编辑 `.docx`；设置纸张、页边距、中文字体、标题层级、表格与页脚 |
| PDF | 生成 PDF；若由 Word 转换，保留 `.docx` 源文件，除非用户要求仅保留 PDF |
| 页数或单页约束 | 通过内容压缩和版式调整达成，不以缩小到不可读字体规避 |

生成办公文档时，可使用工作区依赖中的 `python-docx` 等工具；不得修改用户的原始附件。需要图像、图表或专用模板时，先读取现有资产并保持风格一致。

### 5. 自检与交付

按文体完成语义检查，并执行可机械验证的项目：

| 检查项 | 适用条件 | 验证方式 |
|--------|----------|----------|
| 事实与主张 | 全部 | 抽查关键数字、时间、头衔和能力表述是否有证据支撑 |
| 结构与受众 | 全部 | 对照交付契约和模板，检查是否回答用途所需信息 |
| 链接 | 含 `[[wikilink]]` 的 Markdown | 运行 `.scripts/check_wikilinks.py <file>` |
| Word 文本 | `.docx` | 用文档解析工具确认标题、正文、表格及关键段落均存在 |
| 页面与版式 | 指定 Word/PDF 或页数时 | 实际渲染为 PDF，检查纸张、页数、截断/重叠和可读性；必要时查看预览图 |
| 文件可用性 | 全部文件 | 确认目标文件存在、可打开、路径在交付说明中明确 |

检查失败时定向修复后复验。无法执行渲染时，须明确报告限制，不能声称已验证页数或版式。

---

## 修改工作流

1. 读取用户指定原稿及其格式约束；
2. 提取修改意图，区分“事实更新、结构调整、措辞润色、版式调整”；
3. 仅对新增或改动的事实补充检索与证据核验；
4. 保留用户未要求更改的有效内容与版式，避免无关重写；
5. 按本规范第 5 步对受影响内容和目标格式复验。

---

## 输出、存放与日志

- 写作产物存放在 `projects/`，不放入任何 `raw/`；
- 在最终答复中给出绝对路径、文体/格式、已执行的验证，以及未能验证或待补的事实；
- 默认不将纯写作产物追加到知识库操作日志，以免把外部交付物误作知识库事实；若写作同时修改项目过程文档，按对应项目的日志规范记录；
- 写作完成不自动摄入。用户要求摄入时，重新按 Ingest 路由并遵守 raw 不可修改红线。

## 能力边界

| 能做 | 不能做 |
|------|--------|
| 基于可追溯材料生成公文、讲稿、简历、简介和合作材料 | 编造不可追溯的经历、数据、资质或国际影响 |
| 在 research 状态中按需起草或修改论文，并组合学科写作 overlay | 把写作能力当作研究证据、实验结果或事实来源 |
| 生成并验证 Word/PDF 等用户明确要求的格式 | 自动发送、提交、签署或代表用户作出承诺 |
| 将多项事实压缩为保守的能力概括 | 把学术服务经历夸大为国际组织任职或政策制定经历 |
| 修改既有文稿并保留未涉及内容 | 未经明确指令将写作材料摄入知识库 |
