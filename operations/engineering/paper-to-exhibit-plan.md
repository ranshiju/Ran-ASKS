# 论文到科普展板：全流程落地计划

日期：2026-10-22。状态：P0–P4 已实现并完成 MPE 受管试点；P5 工程验证已完成，实际预览接受、真人试读与另一篇真实论文泛化仍待完成。本文不构成成品接受、科学批准或公开展示许可。

## 1. 目标与完成标准

把已有论文摄入、展板协作、插图、建议型审阅与本地导出能力接成一个可接续的用户流程：

**提供论文 → 对话明确传播动机 → 核实科学贡献 → 设计故事与类比 → 制作完整展板 → 独立读者试读 → 判断建议并修订 → 新旧对比与必要复测 → 接受实际预览并交付。**

不是一键把论文缩写成海报，也不是让审阅子 Agent 决定作品是否通过。宿主负责对话、科学判断与创作，程序负责确定性工作。允许讨论往返，不新增逐步审批链或另一套任务状态机。

首个完整支持范围：单篇已受管摄入的公共 academic 论文、中文 A1/A0 竖版、可编辑图文与受控位图混排、PPTX/PDF/PNG 本地交付。现有其他文本审阅用途继续保持。

三类验收分别报告：

- 工程完成：来源、资产、版本、成品、审阅和采纳记录能连通；中断能接续；错误不冒充成功。
- 传播效果：能检查读者实际复述、形成的图景和理解断点；修改前后有具体证据，不承诺每次意见都会带来改善。
- 用户决策：接受实际预览、科学确认与公开许可分开记录；模型意见、机械校验或交付均不替代这些决策。

## 3. 用户实际经历的流程

| 环节 | 宿主 Agent 的工作 | 保存或产生的结果 |
| --- | --- | --- |
| 进入与恢复 | 找到已有项目、论文与当前展板；未摄入时使用原 ingest；已有任务先 resume | 唯一展板 store、受管来源、当前版本与缺口 |
| 动机讨论 | 通过提问与自由对话明确面向谁、在哪里看、愿意看多久、希望带走什么、交付什么 | 现有 brief，区分 confirmed/proposed/assumption/unknown |
| 科学提炼 | 回到 Raw 核实问题、做法、发现、意义、适用条件和证据强度 | 复用 plan/content 的 claims，不建立第三份事实清单 |
| 故事设计 | 从观众为什么关心进入；选择类比或其他表达，设计递进关系和阅读路径 | 方案、类比映射及不对应之处、每幅图的独立作用 |
| 完整制作 | 在已有真实授权范围内生成文字、原生图形与必要插画，编译正式完整展板 | 同源 PPTX/PDF/PNG、素材快照、成品 manifest |
| 独立试读 | 只给实际整板和必要读者简报；新上下文不见作者解释和预期答案 | 受管 review 记录、读者复述、直觉图景、卡点、优点及可选建议 |
| 修订判断 | 区分观察、猜测、审美偏好和待核实事实；采纳、部分采纳或拒绝并解释重要取舍 | 原始意见不变，采纳判断与修改绑定新 revision |
| 对比与复测 | 展示整板与重点局部差异；关键故事修改后在授权范围内重新盲读 | 新旧成品绑定、变化说明、复测结果或明确未复测 |
| 接受与交付 | 用户看过实际预览后记录真实接受，交付绑定的文件版本 | 正式交付包；科学及公开许可仍保持各自真实状态 |

讨论仅询问真正影响方案且尚不明确的问题，不一次发送完整问卷。一次明确的“按这个方案制作并试读、修改”可以覆盖对应工作，不要求用户逐条签字；制作授权不能推导预览接受。

## 4. 架构与责任边界

### 4.1 Agent/shared/API

- **Agent-only**：动机澄清、科学提炼、故事与类比、图意与提示词、实际子 Agent 委派、科学表达核对、采纳决策和面向用户的解释。当前宿主持有控制循环。
- **Shared**：输入定位、快照、严格协议、素材绑定、布局编译、机械校验、任务交接、记录接收、版本失效、报告、比较与事务回滚。不能模拟读者或评价科学推理。
- **API-only，可选**：沿用已有显式授权的图片生成和旧展板 API reader；不隐式回退、不因子 Agent 不可用而自动外发，不把旧接口的两个固定受众强加给新通用功能。

不新增顶层工作类型、外部 Agent 控制器或大一统 pipeline 状态库。用户仍从 `artifact.science_exhibit` 进入，组合 `artifact.review`、illustration 及已有 ingest；Route、WG 与 resume 提供准确的下一动作。

没有原生图片交接能力时明确 unsupported。Agent 处理不等于本地处理；新上下文、材料范围、工具强制范围和处理位置分开记录。private、未知敏感性不进入本次新增图片通道。

### 4.2 单一事实与创作来源

- Raw 与受管附件继续是事实依据，禁止直接修改 Raw。解析/OCR 错误先核对原始材料，不能归为论文错误。
- 展板 store 是需求、方案、内容、确认和反馈的唯一创作状态；workspace 只保留事项与接续入口。
- 文案、布局、素材与 review 都绑定实际版本；公开文件不夹带内部 Raw 路径、审阅原文或本机信息。
- 关键科学说法保留 claim 与限定语；示意图、类比和 AI 插画如实标识，不冒充实验装置、数据或实物照片。

## 5. 需要补齐的最小充分契约

### 5.1 对话形成有效简报

复用现有 brief 的 goal/audience/setting/delivery/constraints 等槽位；阅读预算和希望保留的直觉写在相应语义字段，确有跨任务需要才增加版本化字段。review 的有效简报从这些已明确需求派生，不另维护一份可能漂移的受众画像。

角色职责稳定：先复述、呈现图景、定位断点、指出有效表达、允许无建议。受众、时长和本次传播目的按任务配置，不为“本科生五分钟”另建执行器。

作者希望读者形成的具体解释、类比标准映射及旧意见保留在宿主侧，不传给 blind reviewer。必要的任务目标可以提供，但不能夹带答案。

### 5.2 内容与自由叙事布局

保留问题、方法、发现、边界等内部语义职责，解除其与“四个固定可见框”的绑定。允许用三幕故事、连续主图或主图加解释组织 A1/A0 版面，不让工具模板反过来决定科学故事。

在展板布局层扩展有界混排协议：原生文字/形状/连线、受控位图、分组和显式层级。文本与科学标注引用唯一内容 ID；布局不重复维护另一套正文。复用现有 artwork validator，不把任意文件路径、脚本或 HTML/XML 执行能力塞入通用 artwork。

新的协议采用显式版本，现有 flow/concept 与 v1/v2 读取、导出和在途任务保持兼容；旧包按既有规则显式升级，不自动改写。

### 5.3 素材与正式混排导出

优先复用已有 illustration 产物或用户授权素材，不默认自动抓取论文图片。素材经白名单格式和实际解码检查后冻结，绑定哈希、实际尺寸、来源、生成方式和已知使用限制；路径必须受管，拒绝越界与符号链接。

文字、标注、箭头、边框保持原生可编辑；照片和插画保留图片对象，不承诺把位图内部内容变成矢量。不得用一整张 PNG 冒充可编辑 PPTX。

PPTX 是正式编译产物，PDF 从同一份 PPTX 导出，PNG 从实际成品生成。检查物理尺寸、字体、正文与限定语、边界、图片比例、裁切、对象层级及有效分辨率；清晰度要求按实际用途约定，不以像素放大冒充印刷质量。不承诺 PDF/X 或印厂色彩认证。

### 5.4 正式图片 review

在现有 review material/packet 契约中增加显式图片分支，首批支持实际单张整板 PNG，原文本分支保持兼容。冻结实际输入字节、尺寸、审阅定义、有效简报和成品绑定；若规范化或缩放，另记录实际交接表示与处理方式，不静默裁图或压缩。

宿主使用原生图片附件交接，不要求 reviewer 开工具读本机路径。不传作者解释、参考答案、论文全文或其他审阅结果。未实际传入或不可辨认时返回技术限制，不能用 OCR 或专业背景假装读图。

公共反馈不增加科普必填字段；在 reader-comprehension 的专属扩展中演进 mental picture、图中位置和阅读断点表达。版本升级不能破坏已有文本任务与冻结反馈 schema。

只有实际候选通过原 check/collect 后才标记审阅完成；原始反馈与宿主解释分离。图片定位采用可见区域描述和可选归一化区域，不套用文本行号，也不声称机械定位证明意见正确。

### 5.5 采纳、比较与接续

采纳记录引用 run、意见 ID、输入成品 manifest 和修改 revision；支持采纳、部分采纳、拒绝、暂缓。不要求关闭全部意见，不把未采纳变成失败。

对比从实际旧/新成品生成，包含整板、必要局部、文案变化、素材变化和重要取舍。像素差异只描述变化，不计算理解质量分数。

resume 汇总现有权威状态并给出后续动作，不另保存 pipeline 进度。来源、受众、故事、资产、布局、字体或 renderer 改变，按依赖使旧接受失效；旧 review 保留，只能解释其冻结旧输入。收集旧意见不意味着适用于新稿。

## 6. 实施批次与依赖

批次是工程拆分，不是新增用户审批节点。每批开始重跑 impact，按当前实际工作树调整范围；新增组件或改变边界时先登记 `operations/engineering/graph.yaml`，再实现。

### P0：统一契约与接续路径

- 精读 science-exhibit、review、illustration、source locator 与实际编译器责任边界，确认协议版本方案。
- 定义新增素材/布局/图片输入与成品绑定契约，更新工程图和定向工程文档。
- 把“从论文进入”和“恢复已有展板”纳入同一入口提示，保留原功能 ID，不登记名义上完成的新功能。
- 验收：组件责任、兼容策略、失效关系和测试样例明确；现有用户路径不发生隐式后端变化。

### P1：对话、证据与叙事接通

- 改善 brief/plan/content 的宿主任务与 resume 指引，复用既有确认记录。
- 从同一来源核对贡献、证据层级与边界；形成受众化故事及可选类比映射。
- 提供没有类比、不同受众和非物理论文样例，避免把 MPE 深海故事硬编码为规则。
- 验收：从未填完的需求可以继续讨论；默认值不冒充用户确认；方案能解释“为什么这样讲”，不只返回 schema。

### P2：受控混排与正式成品

- 扩展内容到布局的映射，支持自由故事分组而保留科学证据关联。
- 复用 illustration 素材元数据，完成资产冻结和位图对象编译。
- 编译同源可编辑 PPTX/PDF/PNG，扩展 manifest、机械回读和失败回滚。
- 验收：MPE 同类三幕混排可以从已提交创作数据重新 build，不依赖 temp 合成脚本；文字可编辑、三类输出一致，旧导出继续可用。

### P3：受管图片审阅

- 扩展 review 的图片快照、packet、check/collect/report 与角色专属 schema。
- 接通实际整板附件交接和子 Agent 调用记录；合成测试与真实宿主验证分列。
- 继承已有权限声明、未知能力处理、幂等、冲突、过时和恢复规则。
- 验收：实际图片闭环成功；图片未传入/无法查看不能得到伪成功；旧文本 review 回归不破坏；旧 API reader 不被暗中改成新默认。

P2 与 P3 在 P0 契约确定后可独立推进；P4 同时依赖两者。本计划不要求创建并行子 Agent 或新任务。

### P4：意见到修订、对比与复测

- 连接真实 run、采纳说明和新版本，保留原始反馈。
- 自动完成机械性的整板/局部对比及文案、资产变化报告；语义取舍仍由宿主解释。
- 在授权内安排首稿试读与一次关键修改后复测；小字改动不自动调用，继续增加轮次须说明收益，不形成无限自我审阅循环。
- 验收：可追溯“哪条意见、为什么采用、改了什么、是否复测”；负面或无改善结果可正常保留，不刷到模型满意。

### P5：真实闭环、泛化与交付验收

- 用 MPE 完成正式混排导出、受管图片试读、必要修订、比较和接续演示。
- 用另一篇已授权、已摄入且体裁或学科不同的论文验证，不擅自选择敏感稿件；未获得输入时用合成样例验证工程，真实泛化保持未验证。
- 完成针对性回归、运行时目录、工程图及公开树检查，更新长期契约和使用示例。
- 用户实际看过对应正式预览后才登记接受与交付；无人类接受指令时止于待评预览，不伪造全流程完成。

## 7. MPE 试点的具体检验问题

沿用已讨论的传播目标：一般本科生、五分钟以内、主线清晰、借直观图景理解工作内核，不要求掌握技术细节。深海故事是已选方案，不是以后展板的默认类比。

- 承接 `projects/MPE科普展板/exhibits/mpe-2026`，先读取 workspace status 和 resume；不重置 revision 39 的真实历史。
- 第六版讨论稿可作为明确来源的素材和设计参考，经新契约提交后重新正式 build；不把旧 SVG/PNG 伪登记为已编译正式预览。
- 检查“参照像普通数轴”的歧义是否减少。
- 检查新增单层例子是否真正补上直觉过渡，还是增加了本科生的技术负担；允许结论是需要换讲法，而不是继续堆解释。
- 新旧比较若用于理解观察，给两个新上下文分别相同受众简报及各自整板，不互见版本或反馈；这仍不是统计因果实验。
- 条件允许时请少量真实本科生自由复述和指出停顿，单列人类反馈；没有真人反馈就保持“真人有效性未验证”。

## 8. 风险与处理

| 风险 | 处理原则 |
| --- | --- |
| 类比顺畅但科学错误 | 先核实贡献及条件；检查类比保留了什么关系、哪里失效，不用新故事补造事实 |
| 模型替作品补全知识 | 先复述、说明不确定与借用背景；不把角色设定当真实认知能力限制 |
| 有用建议导致过度技术化 | 用传播目标约束采纳，复测新增理解负担，不默认解释越严密越适合普通读者 |
| 四框模板绑架叙事 | 内部语义与外部排版分开，先设计理解路径再映射受控布局 |
| 混排素材不清晰或不明来源 | 冻结来源与尺寸，检查实际裁切及有效分辨率，未知许可不自动提升为可公开 |
| 审阅独立性被夸大 | 分列新上下文、材料范围与权限，未知 model/usage/location 如实未知 |
| 流程变得更繁重 | 封装机械交接、比较与恢复，复用同一事实与创作状态，不新增调度/审批系统 |
| 导出或审阅中断 | 明确已提交与未提交产物；恢复不重复调用模型，不覆盖旧正式成品 |
