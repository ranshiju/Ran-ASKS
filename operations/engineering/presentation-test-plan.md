### 目标与不变边界

- 用户能通过会议、报告人、报告题目、研究主题找到原始 PPT，并定位相关页。
- 原件生成同名忠实 Markdown companion；报告摘要和主题导航进入 Wiki，事实引用回到受管 Raw。PPT 内备注、可见正文和视觉补充各自标识，不把摘要、设计评价或 API 回执当作原始事实。
- 主 Agent 组织任务、理解文字结果与调用工具；视觉识读、版式理解和可见缺陷判断使用独立 API adapter。Agent 主控制循环不切换至 DSH/API 编排器，视觉失败不自动改用宿主看图。
- 学术报告先复用 academic-reference；报告中的会议信息作为可检索内容，不把整份报告分类成 conference-summary。学术会议 PPT 属 ordinary 来源，不能仅因“会议”二字变为会议语音纪要。
- PPT形式检查、PPT证据核查、PPT引用脱敏继续独立。最终形式检查与引用脱敏只在用户明确要求时执行；证据核查仅处理用户疑问。摄入保真和制作中的预览检查不冒充最终形式检查或用户批准。
- 模板收藏依据用户选定范围；摄入可以推荐候选，但不自动收藏全部页面。单次报告归档与模板收藏分别提交，收藏失败不撤销已成功的报告归档。
- 首版处理静态 PPTX；动画、视频、任意 SmartArt 重建、扫描图精确反推原生数据和完整主题自动生成不作承诺。

| D：报告摄入与检索 | 将 API 内容回执接入 ingest_document 原事务；受管归档原件、companion、来源 sidecar；生成报告信息、摘要与页码导航；复用现有图和查询入口 | 会议、报告人、主题三类查询均能返回原件和相关页；缺失信息留空；会议宣传页不污染主会议身份；中断恢复无重复归档 |
| E：模板提取与收藏 | 对用户选定页提取 PPTX、设计说明 MD、结构 JSON 与可重建缩略图；扩展现有 slide-library 索引与去重；建立受管收藏命令 | 选定页关系依赖完整、对象可编辑范围真实；能按布局与组件查找；重复收藏幂等，同版式不同内容不误删；不改原件 |
| F：制作接入与闭环验收 | 制作前可读取模板设计说明；将 state 预览视觉记录和 delivery 形式检查接到 API 回执；支持理解修改前布局与用户显式要求的改后检查 | 保留内容/设计/锁页确认；API pass 不等于用户同意；默认导出不触发三项辅助操作；完成真实应用打开与选定对象编辑验收 |

依赖为 A → B → C → D → E → F。D 完成即交付“报告可检索”；E 完成再交付“模板可收藏”。复杂模板的通用槽位自动替换单独评估，不把原生页复制当作现有三版式 IR 的无损导入能力。

### 伴生文档与数据分层

- Raw 包：原 PPTX、同名 Markdown 和来源 sidecar，经现有事务提交；保留原文件名和来源路径。companion 按实际页序组织正文、表格、独立备注、图片转写与必要的忠实图意描述。视觉转写与解释标明身份和未确定项，不覆盖原生文字；主会议等归纳字段在 Wiki 中组织。
- Wiki：题目、报告人/单位、会议名称、报告日期、地点、主题摘要、主要结果、逐页或分段导航、原件入口。字段附证据页，允许未知；报告日期、会议起止日期、源文件日期与摄入时间分别处理，不借用文件系统时间。中文检索别名与英文题目并存。
- Graph：复用现有受管语义槽及实体解析，保留报告与主题、人物、已有会议页之间的必要关系；不逐张幻灯片建立图节点，不引入第二套事实检索库。提及人物或单位不自动推定主办、报告或参会关系。
- temp：渲染 PDF/页图、结构解析缓存和完整 API 执行回执；可重建，不作事实来源。摄入保留持久来源绑定和质量限制，删除缓存后仍能查询原件及 companion。
- slide-library：所选页面 PPTX、同名设计说明 MD、结构 JSON、缩略图及现有索引。记录源 Raw 路径、原始页码、源版本哈希及组件版本；设计分析属于派生物，不能反向作为研究结论依据。

### 视觉 API 的具体协议

1. 内容识读：结构检查覆盖全部页；需要视觉补充的页由 API 看图，包括图片承载内容、复杂关系、未支持对象和提取缺口。纯文字且机械检查充分的页可记录“结构提取完成、未做视觉识读”，不能伪称 API 已复核。
2. 版式解析：输入页图、原生对象 ID/边界/文字样式与任务，返回区域角色、阅读顺序、视觉层级、组件用途、内容容量建议和复用限制。先全页适当分辨率建立上下文，仅对不清楚的局部裁剪放大；裁剪坐标映射回原页。
3. 形式检查：返回可见问题、严重度、页码、归一化区域、可对应的对象 ID、依据和修改建议。纯审美建议与阻碍阅读的缺陷分开；无法对应对象时保留区域，不编造 ID。批准预览对比须真正提供并绑定两份输入。
4. 程序写入实际模型、任务模式、时间、prompt/schema 版本、源/渲染/结构哈希、完成状态及用量；模型不自报“用户已同意”。记录图像接收与响应错误，截断、超时、非法 JSON 均非通过。
5. 分离语义 backend 与视觉 backend；主/回退模型复用现有配置，PPT 专项效果经样本验证，不因已有 OCR/通用 QA 测试而宣称已适配。失败调用和补充裁剪有明确上限；用样本测得延迟、调用数、费用后确定默认预算。
6. 授权范围覆盖所选材料、页码、模式和必要输入；沿用本会话明确授权，不重复询问。现有图片 OCR 持续许可不自动扩展至 PPT；不把 local_only 全局改成可上传。private 继续物理隔离；无有效授权或 API 失败返回文字任务，不转交宿主看图。
7. 缓存绑定页内容、母版/主题依赖、渲染器/字体、结构数据、任务参数、模型与协议版本；改变任一依赖不得错误复用。最终回执始终绑定当前整份来源，跨版本页级复用须重新确认映射。普通续做复用已完成页；新网络重试遵守显式预算。

### 模板结构提取要求

| 项目 | 确定性提取 | API 分析与限制 |
|---|---|---|
| 字体字号 | run/段落样式，主题与母版继承，中西文字体，粗细、颜色、行距和项目符号；区分声明字体与实际渲染字体 | 评价实际可读性与层级；无法解析的字体不让视觉估计冒充精确值 |
| 页面布局 | 画布尺寸/比例、对象边界、旋转、组合变换、层级、边距、对齐与间距，采用绝对值及归一化坐标 | 区分标题/正文/主图/结论等角色和阅读顺序；处理合理叠放 |
| 页面利用率 | 将内容边界裁到画布，排除背景/装饰、按区域求并集，报告覆盖比例、留白与分区密度；保留排除依据 | 指标注明几何估算，图片内部留白等另标限制；不设全局“越满越好”阈值，不把面积比当可读性评分 |
| 表格 | 单元格、合并关系、列宽行高、边框填充、数值格式、文字样式 | 判断表头角色、信息重点和阅读负担；图片表格单独标为栅格 |
| 图表 | 原生图表系列、轴、图例、样式以及可读取的缓存/内嵌数据；外部链接只记录，不自动访问 | 解释用途与图例；图片曲线不生成伪精确数据；数据缺失、缓存可能过期须标明 |
| 框图 | 原生节点、连接端点/箭头、组、形状与样式 | 判断流程、层级、反馈等语义；几何连接不自动证明因果关系 |
| 示意图 | 原生组合与位图素材、裁剪、大小、位置及依赖 | 描述组成、意图、替换区域；区分原生可编辑、混合、整图引用 |

模板原样收藏与通用占位模板分别记录版本。保存原样页不自动替换姓名、会议、日期或引用；通用化只按用户指定内容范围实施，不等同于 PPT引用脱敏。复制须保留母版、主题、嵌入图表/媒体、关系与备注依赖；不支持无损提取时显式报告，不静默扁平化为图片。

模板去重先比源版本/页码和内容哈希，再推荐版式相似候选；用户可选择复用、新增或另存版本。单页写入完整临时目录后原子提交，索引更新可恢复；中断不能留下索引指向半成品，source 变化需重新提取。

### 代码与规范影响清单

- shared：pptx_document.py（结构及忠实提取）、visual_qa.py（既有渲染/通用 API 基础）、ingest_document.py（事务接线）、source_locator.py（验证实际 companion 页标题定位是否足够，按缺口修改）、presentation_state.py / presentation_delivery.py（回执校验与执行身份）。
- API-only：PPT 专项视觉调用 adapter；shared 管 schema、输入哈希、预算/缓存/校验，不模拟 Agent 语义判断。Agent-only：调度、摘要整理、模板用途选择与用户交互，读取 API 文字结果。
- 模板工具：在既有 slide-library 下新增受管提取/提交入口，先登记工程节点与测试，不另建平行模板库。
- 文档：INGEST.md、INBOX.md、PRESENTATION.md、VISUAL_QA.md、academic/SCHEMA.md、slide-library/_rules.md / _index.md、工程图与调用指南；若触及公开镜像同时同步。路由只加载当前动作所需规则。
- 兼容：旧宿主回执保留真实历史身份；新 API 回执使用版本化协议。旧事务恢复不得伪造 API 已执行；旧模板说明不强制批量重写；不搬移已有 Raw 或重写其来源。

### 验收矩阵与交付顺序

| 编号 | 用例 | 通过标准 |
|---|---|---|
| AP-01 | 原生结构与伴生 MD | 页数/页序、隐藏页、备注、表格、对象绑定正确；未知项可见；原件不变 |
| AP-02 | 样式继承、组合旋转、背景与重叠 | 合成 fixture 得到预期字体/字号/边界；满页背景不使利用率变成 100%；面积不重复累计 |
| AP-03 | API 三模式与失败 | mock 验证协议、身份、无宿主看图回退、失败不通过；live 单独验证真实可见问题和转写，不以 mock 声称视觉质量通过 |
| AP-04 | 摄入事务与恢复 | 沿用原 validator/commit；失败不产生半套 Raw/Wiki/图；resume 不重复付费已完成页或重复落位 |
| AP-05 | 检索 | 按会议/报告人/主题均可到达原 PPT 和相关页；复用现有查询，日常文字查询不调用视觉 API |
| AP-06 | 模板依赖、索引和重复 | 原生文本/表格/连接线及图表依赖保留；栅格如实标识；重复收藏与中断恢复安全；旧模板继续可用 |
| AP-07 | 形式检查与锁页 | 回执绑定最终预览及批准预览；旧哈希拒绝；API 结果不冒充用户确认；默认导出不触发三个辅助动作 |
| AP-08 | 权限与隐私 | scope 不扩到其他文件/模式；受保护来源无授权不发送；密钥与 data URL 不进日志；不破坏 private 隔离 |
| AP-09 | 实际 PowerPoint | 用户打开提取模板无修复提示，并能编辑声明为原生的代表性对象；字体替代/平台差异如实记录 |

实际样本先选封面、并列比较、原生表格、图片结果、复杂框图等 5–6 页完成 C 的内容/版式试验；记录人工指出的漏项、错误、调用数与延迟，确认协议适用后再运行整份报告。主 Agent 不看图；人工验收由用户完成，不用 API 自评或程序通过代替。

样本主要验收“报告信息没有混淆其他宣传活动”“主要研究内容可检索”“图与备注没有遗漏或混写”“已有三页引言组件不重复收藏”。具体文件内容留在本地受管材料中，不进入公开测试 fixture。

各阶段运行责任组件的针对性回归，代码改动完成后统一 validate 工程图。B/D 重点为 test_pptx_document.py、test_ingest_document.py、test_inbox_finalize.py；C 为 test_visual_qa.py 和新增 adapter 测试；E 为新增模板事务测试；F 为 test_presentation_state.py、test_presentation_delivery.py、相关 route 测试。shared 测试不发真实网络请求；live API 与真实应用验收另报状态。测试名称/新增命令以实现时登记为准。

首个交付点为 D：原件＋可信伴生 MD＋可检索报告卡。第二个交付点为 E：用户选定页面＋设计参数＋模板检索。第三个交付点为 F：模板辅助制作和 API 视觉闭环；不以此宣称任意模板自动套用、整个制作阶段或人类验收已经完成。
