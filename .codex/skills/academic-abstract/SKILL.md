# 学术论文摘要撰写与修改

在 WikiGraph 仓库内使用。方法规范的单一维护源是[学术摘要规范](../../../operations/research/academic-abstract.md)，不把当前论文数字或历史候选摘要复制成模板。

## 入口

遵循仓库 playbook、路由和项目上下文恢复约定。保持当前 `research` 工作上下文；明确用户要求的是讨论、起草还是修改。延续上一轮时，以当前指定版本和已接受意见为准。

- 讨论：读取上述规范及支持问题的论文内容，提供判断、证据与推荐表述，不自动写文件。
- 起草或修改：加载下列 profile，按返回规范完成交付；同一连续回合已加载则复用。

```bash
python3 .scripts/route.py --capability write --capability-profile academic-abstract
```

该 profile 由宿主 Agent 执行语义工作，没有自动 API 后端或独立模型评审。按实际学科组合相应写作 overlay；物理论文使用 `operations/research/physics-manuscript-editing.md`。

## 材料与完成条件

首次实质改稿前按摘要规范复用 `manuscript-evaluation`，先展示核心科学问题、贡献分类与重要性评分、证据强度和推荐主线；按规范处理定位确认，复用已接受判断。仅语言或格式校正不重做评估。

从原稿、主要结果和必要补充材料确定主张与证据，而不是仅重写旧摘要。缺少数据时不编造，也不将一次基线比较扩大成全面领先。仅讨论时给出可执行的结论；要求落地时交付新摘要、修改说明及适用的源文件、diff 和构建结果。

源文件和导出验证按已有写作规范及可用文档技能完成。保持稿件材料在用户授权范围内，写作结果不自动摄入知识库。
