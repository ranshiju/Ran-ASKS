# 学术论文摘要撰写与修改

在 WikiGraph 仓库内使用。方法规范的单一维护源是[学术摘要规范](../../../operations/research/academic-abstract.md)，不把当前论文数字或历史候选摘要复制成模板。

## 入口

遵循仓库 playbook、路由和项目上下文恢复约定。保持当前 `research` 工作上下文；明确用户要求的是讨论、起草还是修改。延续上一轮时，以当前指定版本和已接受意见为准。

- 讨论：读取上述规范及支持问题的论文内容，提供判断、证据与推荐表述，不自动修改论文；持续讨论按规范更新项目记录。
- 起草或修改：加载下列 profile，按返回规范完成交付；同一连续回合已加载则复用。

```bash
python3 .scripts/route.py --capability write --capability-profile academic-abstract
```

该 profile 由宿主 Agent 执行语义工作，没有自动 API 后端或独立模型评审。按实际学科组合相应写作 overlay；物理论文使用 `operations/research/physics-manuscript-editing.md`。

## 材料与完成条件

按摘要规范整合 `manuscript-question`、`manuscript-evaluation` 与 `manuscript-motivation` 的有效结果，围绕核心贡献回答科学问题。优先复用最新认可的定位，缺失或变化时按需补齐；首次形成定位时展示问题、贡献评估与推荐主线，按规范处理确认。仅语言或格式校正不重做评估。

从原稿、主要结果和必要补充材料确定主张与证据，而不是仅重写旧摘要。形成科学主线与整段质量复核按摘要规范执行，交付前完整通读并与正文及上一版对照。缺少数据时不编造，也不将一次基线比较扩大成全面领先。仅讨论时给出可执行的结论；要求落地时交付新摘要、修改说明及适用的源文件、diff 和构建结果。

逐词逐句审阅按规范的专节执行：先辨实际含义与句子任务，再追问用词、条件、比较和结尾意义，形成推荐改法及收益/取舍，最后整段重读。保存有实质作用的讨论决定并区分建议与落实；凝练的是可迁移判断，不把特定词汇替换固定为规则。

源文件和导出验证按已有写作规范及可用文档技能完成。保持稿件材料在用户授权范围内，写作结果不自动摄入知识库。
