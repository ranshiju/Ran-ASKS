# 论文撰写与优化持续工作

在 WikiGraph 仓库内使用，流程的单一维护源是[论文改进规范](../../../operations/research/manuscript-improvement.md)。遵循仓库 playbook、路由与项目上下文恢复约定，保持 `research` 工作上下文。

- 建立或接续：按专项规范初始化或恢复现有研究工作区，读取当前稿件事项和必要记忆，核对原稿、主稿与候选；先保存当前范围及具体下一步，再推进。
- 讨论或评估：读取上述规范与论文，给出有依据的建议，不自动改文件。
- 实际改稿：加载下列 profile 并按返回规范完成交付；同一连续回合已加载则复用。

```bash
python3 .scripts/route.py --capability write --capability-profile academic-manuscript
```

宿主 Agent 按任务范围阅读稿件或研究材料，复用科学问题、贡献评估与背景动机，按证据和当前薄弱处安排写作顺序。有稿件时基于或参考原稿，最后与原稿及上一版对比；定位确认沿用已有约定，接续复用有效阅读与认可意见。文献缺口随时记录并提出具体需求，授权摄入后回到原工作位置核验、续写，其余可做工作继续。

阶段结束通过受管工作区入口更新产物、进度、待补证据和下一步，稳定决策保存为记忆；通用规范与事项模板在仓库内，其他智能体可按相同入口接续，实际论文和工作实例保持私有。

摘要与引言阶段分别复用 `academic-abstract` 和 `manuscript-introduction`，学科规则按需组合。流程不调用额外模型、不自动启动独立评审；局部修改不自动扩大范围。交付修改文件、关键变化、适用的 diff 与构建检查结果，并如实报告无法通过写作补齐的证据缺口。
